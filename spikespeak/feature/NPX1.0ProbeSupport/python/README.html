spikespeak_postprocess#

Load SpikesPeak recordings — Neuropixels 1.0 AP / LFP bands and NI-DAQ — addressed by the electrode number you saw on screen, as NumPy arrays or xarray DataArrays.

Why it "just works"#

Every recorded .bin file has a self-describing <file>.bin.json metadata sidecar written by the SpikesPeak backend (RecordProcessor) at record time. It carries the band, record layout, sample rate, units, and the channel/electrode list — so this package needs no out-of-band knowledge of the recording.

Install#

cd python
pip install -e .            # core (numpy)
pip install -e .[xarray,plot]   # + xarray + matplotlib for the example

Use#

from spikespeak_postprocess import Recording

rec = Recording(r"C:/Data/mouse42")     # the folder you chose in the Record dialog
rec.bands()                              # ['ap', 'lfp', 'nidaq', 'nidaq_di']
rec.channels("ap")                       # electrodes recorded for AP, e.g. [1, 2, 3]

# --- NumPy ---
sig = rec.load(channels=[1, 2], band="ap", output="numpy")
sig.data            # (n_samples, 2) int16 ADC
sig.time            # (n_samples,) seconds
sig.channels        # [1, 2]  (electrode numbers, column order)
sig.fs              # 30000.0
uv = sig.to_microvolts()                 # (n_samples, 2) in µV

# LFP electrode 2, and all NI-DAQ channels
lfp = rec.load(channels=2, band="lfp")
daq = rec.load(band="nidaq")             # all recorded NI-DAQ analog channels (volts)

# --- NI-DAQ DIGITAL lines (DI/O) ---
# The NI-DAQ port0 lines are recorded as the "nidaq_di" band: each channel is a 0/1 logic line
# (e.g. the Neuropixels 1.0 sync pulse rides one of them). It loads as a digital Signal.
rec.digital_lines("nidaq_di")            # {0:('high',0), 1:('low',0), 2:('toggling',N), ...}
di  = rec.load(band="nidaq_di")          # di.units == "logic", di.digital is True, values are 0.0/1.0
hi  = di.as_bool()                       # boolean (n_samples, n_lines); to_microvolts() is refused
sync = rec.load(channels=2, band="nidaq_di")   # just the toggling sync line

# --- xarray ---
da = rec.load(channels=[1], band="ap", output="xarray")   # dims (time, channel)

channels are electrode numbers for ap/lfp (what the live view shows; equal to the read-out channel for the default Bank-0 map) and channel indices for nidaq. Requesting an electrode that wasn't recorded raises a clear error listing what was.

Synchronizing NI-DAQ ↔ Neuropixels (clock-drift correction)#

Feed one shared TTL/sync pulse train to both the Neuropixels sync input (recorded in the NPX sync field) and one NI-DAQ analog channel. The same pulses then appear in both files, so their rising edges pin the two clocks together and correct for drift:

model = rec.synchronize(reference_band="ap", nidaq_sync_channel=0)   # NI-DAQ ch 0 carries the pulses
print(model.drift_ppm, model.residual_ms)     # e.g. -51.3 ppm, 0.02 ms RMS  (alignment quality)

daq = rec.load(band="nidaq", sync=True)        # daq.time is now on the Neuropixels clock
# or apply the map yourself:
t_npx = model.apply(daq.raw_timestamps / daq.fs)

This ports polling-latency.ipynb's align_with_drift_correction with improvements: - Linear warp by default — clock drift is a near-constant rate, so a least-squares line is robust and won't blow up on extrapolation the way the notebook's quadratic interp1d can (kind="quadratic"/"interp" reproduce it; "interp" needs SciPy). - Adaptive edge threshold (per-signal min/max midpoint) — handles a 0/1 NPX bit and a several-volt NI-DAQ analog pulse without tuning. - Robust nearest-edge pairing by default (match="auto") — pairs the two pulse trains by nearest edge, so a capture-count asymmetry at either end can't cause the off-by-one that silently shifts latency by a whole sync period. A pulse-count mismatch (and any residual interval disagreement) is warned about, not hidden; match="end"/"start" remain for explicit one-to-one end/start pairing. - Diagnostics — drift_ppm and residual_ms so you can see the alignment quality (residual should be sub-millisecond).

The low-level function is exposed too: align_timestamps(ref_time, ref_sync, target_time, target_sync, kind="linear", match="auto"). Example with the before/after verification plot: python examples/synchronize_nidaq.py <dir> [ch] [band].

Example — plot a channel#

python examples/plot_channel.py C:/Data/mouse42            # random AP electrode
python examples/plot_channel.py C:/Data/mouse42 lfp 2      # LFP electrode 2
python examples/plot_channel.py C:/Data/mouse42 nidaq 3    # NI-DAQ channel 3

Example — save the two standard plots into a recording folder#

python examples/plot_recording.py C:/Data/mouse42          # writes sync.png + channels.png in that dir

sync.png = NI-DAQ↔NPX timestamp sync (before/after drift correction); channels.png = the recorded AP electrodes over the first 2 s on a shared µV scale (so a noisier/damaged channel stands out). 12×4-inch PNGs. Robust: if there's no shared sync pulse train, sync.png still renders the raw signals.

Record layouts (from the sidecar record_format)#

record_format bytes per record units
npx uint32 ts · uint16 sync · int16 × N adc_int16 (→ µV via default gains: AP 500, LFP 250)
nidaq float64 ts · float64 × N volts (→ µV = ×1e6)
nidaq_di float64 ts · float64 × N (same nidaq format) logic (0/1 digital lines; .digital=True, use .as_bool())

N = number of channels in the recording's channels: list. Microvolt conversion assumes the default IMEC gains (AP 500 / LFP 250); if you change the gain in the IMRO panel, scale accordingly.

Sibling tool: spikespeak_cli.py (headless control)#

python/spikespeak_cli.py drives a running SpikesPeak backend over its WebSocket with no GUI clicking — select → probemap → play → record <dir> <name> → stop → quit — so you can script a whole acquire + record run and then load it back with this package. Zero dependencies (stdlib only). It's how the recording pipeline is regression-tested end-to-end. See developer_docs/ControlCLI.md.
