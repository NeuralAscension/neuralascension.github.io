Synthetic Sources — generating and replaying test data#

SpikesPeak includes two major mechanisms for streaming synthetic data without hardware: generating real-time waveforms (SimulatedDataSource) and replaying recordings (SynthRippleSource).

1. SimulatedDataSource — real-time procedural generation#

source.npx.simdata (NP1.0) and source.npx.sim2 (NP2.0) procedurally generate data in real-time. They are used in the "sine wave" variants to generate simple diagnostic waves, and in the "Ripples" variants to simulate sharp-wave-ripple bursts for the detector.

  • Ripple-scenario knobs are available in the source's YAML node (editable without a rebuild): inject_ripples (bool), ripple_amplitude (ADC counts), ripple_freq_hz (centre of the ripple band), ripple_period_s (injection rate), and noise_amplitude (essential for giving the ripple-band baseline a non-zero standard deviation).
  • NP1 simulation: source.npx.simdata outputs to both data.npx.ap (30 kHz) and data.npx.lfp (2.5 kHz), correctly matching a 1.0 probe.
  • NP2 simulation: source.npx.sim2 outputs to data.npx.raw (30 kHz). proc.lfp handles deriving the LFP band.

2. SynthRippleSource — .h5 file playback#

source.npx.synthripples reads an .h5 file and streams it into the pipeline as if it were coming from a real probe.

  • Choosing the file — two ways (a sim_variant label containing (play file) triggers this): 1. Path line edit — the "Simulated Data" picker shows a text field for a full .h5 path plus a ▶ Play file button. The path travels on the selectSource message as a playbackFile field; the backend uses it directly (no dialog). The last path is remembered in localStorage['rd_playback_path']. 2. 📂 Browse… — leaves playbackFile empty, so the backend opens a native QFileDialog (deferred via QTimer::singleShot(0,…) so it never blocks the WS/QWebChannel loop). The chosen path is echoed back as a playbackFilePicked event and remembered. The backend validates the provided path (QFile::exists) and SynthRippleSource::initData is wrapped in try/catch — a missing/corrupt file streams silence + warns instead of crashing source setup. sPlaybackFile and the published channel map are cleared on closeDataSource (no stale state across sources).
  • Probe Map viewer: SynthRippleSource exposes the same Q_INVOKABLE IMRO surface as SimulatedData2Source (getImroAsJson / getImroAsImroText / updateImroFromJson / applyMapToHardware / loadImroFromText), so the frontend Probe Map tab RENDERS during playback (the frontend binds the npx module on deviceReady and calls these). getImroAsJson returns a default NP2 (probeType 3) or NP1 (probeType 1) map per the bound output. Map edits are accepted but cosmetic — the file tiles across all channels regardless of the map.
  • NP1 vs NP2 Mirroring: initDataSource binds the first outputs[].name and publishes a matching fallback channel map (publishChannelMap(isNp2)): NP2 (data.npx.raw) → NP2 map; NP1 (data.npx.ap) → NP1 bank-0 map.
  • NpxSynthRipples.yaml mimics NP2.0 → data.npx.raw.
  • Npx1SynthRipples.yaml mimics NP1.0 → data.npx.ap + proc.lfp → data.lfp. (The NP1.0 play-file picker option is now enabled — gen_synthetic_ripples.py --probe 1.0 emits the NP1 file(s); see SimulatedData.md §6.)

Playback file format (data/synthetic_ripples.h5) — 2-D per-channel#

SynthRippleSource::initData accepts either shape (row-major, sample-major): - 1-D [nSamples] int16 — one series broadcast identically to every read-out channel. - 2-D [nSamples × nChannels] int16 — each channel its own signal. SynthRippleSource tiles file channel c % nChannels onto read-out channel c, filling all channels (384) regardless of nChannels.

Attributes: sampling_rate int32 (Hz, required), num_channels int32 (optional, validates dim 1). Extra dataset ripple_centers int32 — injected ripple peak sample indices (for correlation).

3. Generating custom synthetic ripples#

scripts/gen_synthetic_ripples.py emits the 2-D HDF5 format with a per-channel bandpassed-noise background + a depth-weighted shared ripple train (Gaussian over channel index with a floor, so ripples are strongest mid-probe yet remain detectable on every channel incl. ch0).

To regenerate/create a custom file:

conda run -n sp python scripts/gen_synthetic_ripples.py --duration 6 --num_channels 384

Note: Use the sp conda env, which has numpy, scipy, and h5py. The default python may lack scipy/h5py, and anaconda base can hit an HDF5 DLL clash.
