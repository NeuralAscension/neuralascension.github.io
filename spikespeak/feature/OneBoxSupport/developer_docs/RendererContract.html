THE LIVE-VIEW RENDERER CONTRACT#

Status: normative specification. Any renderer that satisfies every MUST below is a drop-in replacement for the SciChart implementation in webinterface/ChartColumn.js. Three independent implementations will be written against this document; where it says MUST, divergence is a bug.

Baseline under specification: webinterface/ChartColumn.js:1-832, webinterface/DataStore.js:1-118, webinterface/NetworkClient.js:1-220, webinterface/main.js, webinterface/Config.js, webinterface/style.css, webinterface/toolbar.css, as of branch feature/OneBoxSupport @ 2026-08-26.

Verified during authoring (corrections to the recon digests): - tests/gui/live_view.py:55-71 reads c.surface.renderableSeries.size(), not c.sciChartSurface. The probe was repaired 2026-08-25; the "the suite asserts nothing" claim in developer_docs/NextTask_WasmFrontend.md:211,369 and in digest 3 is stale. §1.6 is therefore a live constraint, not a dead one. - webinterface/Config.js:3-23 confirmed verbatim: TRACES_PER_COLUMN: 20, TRACES_HORIZONTAL: 20, TRACES_VERTICAL: 40, PALETTE = 7 entries. - benchmarks/cdp_bench.py:54-55 reads columns[0].onScreenSeries[0].dataSeries.count(). window.__benchPointCount is documented in benchmarks/README.md:51-52 but is not implemented anywhere. - webinterface/main.js:279-310 is the perf meter (__perfStats/__perfReset), not main.js:140-165 as the planning doc says.

A renderer written against this contract now exists and has been measured: webinterface/GlRenderer.js, see RendererExperiment.md. 5.05x less main-thread CPU at 320 traces, and the frame-rate cliff removed.

1. THE INTERFACE#

1.1 Construction and lifecycle#

new ChartColumn(colIndex, startChannel, channelsPerColumn,
                mainContainerEl, dataStore, onDrawCallback, onColTracesCb)

Call site: webinterface/main.js:616. MUST be pure DOM — it constructs the element tree (§3.2) and appends it to mainContainerEl. It MUST NOT touch the GPU, allocate buffers, or need await.

  • colIndex: int — 0-based; used for the chart-area element id and for onColTracesCb/onColumnPinChanged.
  • startChannel: int — a SLOT index in the depth ordering, not a channel id. buildColumns() staggers it as i * traces (main.js:614). Stored as this.bottomSlot.
  • channelsPerColumn: int|falsy — this.tracesPerColumn = channelsPerColumn || Config.TRACES_PER_COLUMN (20).
  • dataStore: DataStore — stored, never mutated except via the documented fields in §2.4.
  • onDrawCallback: () => void — () => AppController.forceXAxisUpdate().
  • onColTracesCb: (colIndex:int, rawSelectValue:string) => void — the raw string from the density <select>; '' means Auto.

Initial state MUST be: selectedShank = 0, selectedColKey = 'B', currentStreamId = null, userPickedStream = false, selectedChannelIndices = new Set(), onScreenSeries = [], onScreenLabels = [].

await col.initialize()              // main.js:622 — async, MUST be awaited

Allocates the render surface and the fixed pool of tracesPerColumn series + tracesPerColumn label elements. Nothing may call draw() before this resolves.

col.destroy()                       // main.js:588

MUST unbind every series from its data buffer before releasing the surface, disconnect the ResizeObserver, and remove this.container from the DOM. It MUST NOT delete any buffer owned by DataStore — several columns can be bound to the same buffer object.

1.5 Two couplings that MUST be broken, and the exact abstractions that replace them#

These are the only interface changes this contract mandates. All three implementations MUST implement them identically, or DataStore/main.js will diverge per renderer.

(a) Buffer allocation must not go through a renderer handle. Today main.js:646-647 and :762-763 do dataStore.initializeStream(this.columns[0].wasmContext, …) / updateWindowSize(this.columns[0].wasmContext, …).

Normative replacement — the renderer module exports a factory:

// renderer module (one per implementation)
export function createSeriesBuffer(capacity) -> SeriesBuffer

interface SeriesBuffer {
    appendRange(xs: Float64Array, ys: Float64Array): void  // equal lengths, x non-decreasing
    clear(): void
    count(): number                 // samples currently held
    setCapacity(n: number): void    // FIFO capacity change IN PLACE — object identity MUST survive
    delete(): void                  // release; only DataStore may call this
}

DataStore.initializeStream(streamId, numChannels) and DataStore.updateWindowSize(newSizeInSeconds) MUST lose their first parameter and call the factory. FIFO semantics: when full, the oldest sample is evicted; capacity is in points, not seconds.

(b) X range must not be written as an axis property. Today: col.xAxis.visibleRange = new SciChart.NumberRange(max - windowSize, max) (main.js:751-758).

Normative replacement:

col.setXRange(minSeconds: number, maxSeconds: number): void

Called for every column on every processed batch of every stream. It MUST be cheap and MUST NOT force a synchronous layout or a full rebuild. For one transition release a renderer MAY additionally expose col.xAxis = { set visibleRange(r) { … } } accepting any {min, max}; new code MUST use setXRange.

1.6 Probes the test suite and the benchmark read (MUST keep working)#

  • GUI suite, tests/gui/live_view.py:55-71: app.columns[i].surface.renderableSeries.size() must return an integer > 0 for at least one column, and must not throw. A renderer MAY satisfy this by exposing col.surface = { renderableSeries: { size: () => this.onScreenSeries.length } }, or the probe may be re-pointed — but if you re-point it you MUST prove it can fail (unbind a series, watch it go red, revert) per CLAUDE.md.
  • Benchmark, benchmarks/cdp_bench.py:54-55: columns[0].onScreenSeries[0].dataSeries.count(). This one really breaks on a swap. Every implementation MUST additionally expose the renderer-neutral hook already specified in benchmarks/README.md:49-53: js window.__benchPointCount(colIndex) -> number // on-screen sample count for column colIndex, -1 if unavailable and cdp_bench.py MUST call it first, falling back to onScreenSeries (that fallback is documented but unimplemented — write it).
  • Recommended richer probe (developer_docs/NextTask_WasmFrontend.md:369-385), OPTIONAL but wanted by all three: js col.probeRender() -> JSON string of {seriesCount, pointsPerSeries, plotRect:{x,y,w,h}, yForValue(v), colorOf(i)} It may return a Promise but MUST resolve to a string (tests/gui/_harness.py does json.loads).

1.7 Globals and window objects the column calls (MUST keep calling)#

  • window.onLiveFilterChange() → AppController.updateAppendModes(). MUST be called before the next draw() whenever currentStreamId, selectedColKey, or tracesPerColumn changes, or the column renders blank (trap T-3).
  • window.onColumnPinChanged(colIndex, pinned).
  • window.imroLiveView (ImroManager.js:212-233): hasOrdering(), kind(), shanks(), total(), slotOf(ch), channelAtSlot(slot), slotIOf(ch), channelAtSlotI(slot), electrodeOf(ch), shankOf(ch), colOf(ch) (0=L, 1=R), isRef(ch), band(shank, 'L'|'R'|'B') -> {start,count}|null, bandI(shank) -> {start,count}|null.
  • window.rippleModule.beginElectrodeDrag(clientX, clientY, globalElectrode).
  • window.audioModule.listeningChannel(), window.audioModule.setChannel(ch).
  • document.body classes read: ripple-open, audio-open. (no-source is CSS-only.)

2. THE DATA CONTRACT#

2.1 Wire frame (informative for the renderer, normative for anything touching NetworkClient)#

One WebSocket binary message = one frame = one stream, little-endian, IEEE-754 float32 (DisplayProcessor.cpp:291-293, forwarded byte-for-byte by WebSocketServer::broadcastData, WebSocketServer.cpp:797-802):

[u8 idLen][idLen bytes UTF-8 streamId][u32 numChannels][u32 numBins]
then numBins × { f32 tsSeconds ,  numChannels × ( f32 min , f32 max ) }
  • streamId ∈ ap, lfp, raw, adc, nidaq (nidaq_di is specified, not shipped).
  • numChannels is per stream: 384 for a probe band, 12 for the OneBox ADC, device count for NI-DAQ. Never assume 384 (DisplayProcessor.cpp:456-457).
  • min is written first, then max (DisplayProcessor.cpp:458-470; read at NetworkClient.js:133-134). Swapping them still renders — inverted segments — so it fails silently.
  • Timestamp is float32 seconds at the bin MIDPOINT.
  • Units are not on the wire: ap/lfp/raw arrive in hundreds-of-µV (Config.MICROVOLTS_PER_DISPLAY_UNIT = 100); adc/nidaq arrive in volts.
  • Payload start offset is 1 + idLen + 8 — 11/12/14 bytes, not 4-byte aligned, which is why NetworkClient.js:87 copies (new Float32Array(event.data.slice(offset))).

2.2 Rate and volume — what the renderer must sustain#

Quantity Value
Frames per second per stream 50 (20 bins × 1 ms of data)
Timebins per frame 20 (timebins_per_update, 20/20 in every shipped config)
Bin width 1 ms = 100 ticks of the 100 kHz timestamp clock
Points appended per channel per frame 40 (20 bins × min+max) = 2000 pts/s/channel
Bytes/s, one 384-ch stream ~3.08 MB/s (61,532 B/frame for raw)
Worst shipped case NP1 ap + lfp + nidaq concurrently

Each bin contributes two points at the same x, so a bin renders as a vertical min→max segment. Any renderer that assumes strictly increasing x will collapse or mis-draw these.

2.3 Buffers#

DataStore owns, per channel of each stream:

{ dataSeries, dataSeriesInterleaved, yOffset, yOffsetInterleaved, zoom, color, acMin?, acMax? }

Two buffers per channel exist because the vertical offset is baked into y (§2.4): packed depth order and electrode-interleaved order. Capacity (DataStore.js:47-50):

cap = ceil(REFRESH_RATE_HZ(50) * POINTS_PER_UPDATE(20) * 2 * windowSeconds * CAPACITY_BUFFER_MULTIPLIER(1.2))

= 2400 points/channel at the 1 s default, 24 000 at 10 s. updateWindowSize MUST resize in place (setCapacity) so bound renderables do not blank.

2.4 y-baking — the single most important rule#

The vertical position and the vertical scale of a trace are baked into the Y samples at append time by NetworkClient (NetworkClient.js:136-184). The renderer MUST NOT re-offset, re-scale, auto-range, or auto-fit anything. Y values are absolute plot coordinates.

probe (numCh === 384) and streamId !== 'raw':   s = v * channel.zoom
probe and streamId === 'raw':                   AC-couple: envelope min/max with DECAY = 0.9995,
                                                baseline = midpoint, s = (v - baseline) * zoom,
                                                DELIBERATELY NOT CLAMPED
non-probe (adc / nidaq):                        AC-couple as above,
                                                gain = (CHANNEL_VERTICAL_SPACING / NIDAQ_UNITS_PER_ROW) * zoom,
                                                then HARD-CLAMPED to ±0.47 * CHANNEL_VERTICAL_SPACING
y = channel.yOffset            + s   -> dataSeries
y = channel.yOffsetInterleaved + s   -> dataSeriesInterleaved

Consequences the renderer must accept: a zoom or offset change does not alter samples already buffered, so the view re-scales gradually over one window; AppController.relayoutByDepth() (main.js:665-692) sets yOffset = slot * 3.0, yOffsetInterleaved = slotI * 3.0 and then clear()s both buffers precisely because old samples carry the old layout.

Which buffers are fed is gated by dataStore.appendPacked / appendInterleaved, recomputed by AppController.updateAppendModes() from every column's selectedColKey and whether its stream is 384-wide.

2.5 What the renderer does per frame#

Nothing is pushed to the renderer per frame. There is no per-frame draw call in the data path. Per frame the app does exactly: 1. NetworkClient performs one appendRange(xs, ys) per channel per frame into the buffers a column is bound to; 2. AppController.forceXAxisUpdate() calls col.setXRange(latest - windowSize, latest) on every column; 3. one textContent write of the time display.

Therefore the renderer MUST: repaint from buffers it already holds, coalescing to at most one paint per animation frame regardless of how many appends and range writes arrive (50/s per stream, ×N streams — today that is ~600 range writes/s on a 3-stream 4-column config). A renderer that repaints synchronously inside appendRange or setXRange fails this contract.

2.6 draw() — the complete render decision (normative pseudocode)#

Reproduces ChartColumn.js:603-795. Deviations here are visible to the operator and to the GUI suite.

channels = dataStore.streams[currentStreamId];      if (!channels) return
lv       = window.imroLiveView
useDepth = lv.hasOrdering() && channels.length === 384
TRACES   = this.tracesPerColumn

// 1. Filter-control visibility — draw() is the SINGLE owner of this.
show(.cc-shank) = show(.cc-side) = useDepth
toggle('.no-filters') on .column-controls = !useDepth

// 2. Band, slot->channel map, and which buffer to bind
if (useDepth && selectedColKey === 'B')  band = lv.bandI(selectedShank);          chanAt = lv.channelAtSlotI; field='dataSeriesInterleaved'
else if (useDepth)                       band = lv.band(selectedShank, colKey);   chanAt = lv.channelAtSlot;  field='dataSeries'
else                                     band = {start:0, count:channels.length}; chanAt = s=>s;              field='dataSeries'
if (!band) band = {start:0, count:0}

// 3. How many rows are actually on screen
shownSlots = useDepth ? TRACES : min(TRACES, max(1, band.count))

// 4. Paging window
bandStart = band.start; bandEnd = band.start + band.count
maxBottom = max(bandStart, bandEnd - shownSlots)
bottom    = clamp(this.bottomSlot, bandStart, maxBottom);  this.bottomSlot = bottom
topRange  = bottom + shownSlots - 1
shownTop  = min(topRange, bandEnd - 1)

// 5. Slider
slider.min = bandStart; slider.max = maxBottom; slider.value = bottom

// 6. Depth readout (innerHTML)
band.count === 0                -> "(no electrodes)"
useDepth                        -> "<strong>e{electrodeOf(chanAt(shownTop))}</strong>&nbsp;&#8597;&nbsp;e{electrodeOf(chanAt(bottom))}"
else, prefix = (streamId==='adc' ? 'IO' : 'CH ')
                                -> "<strong>{prefix}{shownTop}</strong>&nbsp;&#8597;&nbsp;{prefix}{bottom}"

// 7. Y RANGE — exactly shownSlots rows, traces centred in their row
setYRange(bottom * 3.0 - 1.5,  topRange * 3.0 + 1.5)      // 3.0 = Config.CHANNEL_VERTICAL_SPACING

this.shownSlots = shownSlots
syncLabelOverlayGeometry()          // opportunistic; may no-op before first layout

// 8. Bind, top-first
for i in 0 .. TRACES-1:
    slot   = topRange - i                     // DOM index 0 = TOPMOST = SHALLOWEST
    series = onScreenSeries[i]; label = onScreenLabels[i]
    label.style.top = (((i + 0.5) / shownSlots) * 100).toFixed(4) + '%'
    ch = (slot >= bandStart && slot < bandEnd) ? chanAt(slot) : undefined
    if (ch === undefined || !channels[ch]) { series.visible = false; label.style.display = 'none'; continue }
    series.visible = true; label.style.display = ''
    series.buffer = channels[ch][field]        // BIND BY REFERENCE — never copy, never mutate
    series.stroke = channels[ch].color
    label.textContent / title / handlers  per §3.5

X range is not set here.

3. THE VISUAL CONTRACT#

The replacement must be indistinguishable from today's screenshots at normal viewing. Everything below is a MUST unless marked otherwise.

3.1 Plot area#

  • Background: SciChart's implicit SciChartJSDarkv2Theme — radial-gradient(circle, #3C3C3FFF 0%, #1C1C1EFF 100%) across the chart canvas. It is in no stylesheet; it comes from SciChartSurfaceBase.DEFAULT_THEME in webinterface/lib/index.min.js. Reproduce this gradient explicitly.
  • Padding around the plot: top 0, right 2px, bottom 0, left 2px (SciChart.Thickness(0,2,0,2), ChartColumn.js:291-293 — the argument order is top, right, bottom, left). Left/right are 2 and not 0 so the leftmost stroke and the left:5px label overlay are not clipped.
  • No gridlines. No major or minor. No axis tick labels. No axis line. No annotations. No zoom/pan/cursor modifiers. No legend. The Y axis is invisible; the X axis is nominally visible but draws nothing and only insets the plot rect vertically. A replacement MAY drop the X axis entirely provided the plot rect is what the labels are pinned to (§3.4).
  • Traces: 1 px stroke, no markers, no fill, no anti-alias change, colour = Config.PALETTE[channelIndex % 7] where channelIndex is the read-out channel index, assigned once at DataStore.initializeStream and never reassigned. Palette: #FF4500, #FFD700, #32CD32, #00BFFF, #6495ED, #DA70D6, #FF69B4. Because depth ordering permutes channels into slots, the on-screen colour sequence is deliberately NOT a clean repeating 7-cycle. Do not re-key the palette to the slot.
  • Y direction: NORMAL. Offsets grow upward, so slot 0 (tip / deepest) sits at the BOTTOM and electrode numbers increase upward.

4.5 Acceptance#

A replacement is a drop-in only if, against the freshly re-measured SciChart control on the same machine in the same session:

  1. bound_pts (or __benchPointCount) is > 0 on every cell — the anti-blank-surface guard. Note it saturates at 2400 = calculateCapacity() at 1 s, so it proves "streaming and bound", nothing finer.
  2. fps ≥ control_fps − 1 at every cell.
  3. main_thread_busy ≤ control_busy + 0.02 at every cell, and strictly lower at 4×60 and 4×80 if the renderer is being swapped for performance.
  4. frame_p95 ≤ control_p95 + 1 ms at every cell.
  5. Heap does not grow across the 12-cell sweep.
  6. Both suites green: build.bat → ALL N SUITES PASSED, and python -u scripts/run_gui_tests.py → ALL N GUI TESTS PASSED. Never --hold when automating.

Recommended zero-code experiment before writing any renderer (nobody has run it): sweep window size 1 s → 10 s at fixed series count. That is a 10× change in points per series with no change in draw-call count. If FPS/busy are flat, vertex count is not the cost and per-series overhead is — which decides the architecture.

Also capture, once, the never-recorded decode metrics avgParseMs / maxParseMs / maxGapMs from NetworkClient.js:201-215. They decide whether moving decode off the main thread is worth anything at all.

5. THE TRAPS#

T-1 — The renderer does not own the data. yOffset and zoom are baked into Y at append time (NetworkClient.js:183-184). Y values are absolute plot coordinates. Do not re-offset, do not auto-range, do not normalise. A zoom change does not touch buffered samples; the view re-scales over one window. That is correct behaviour, not a bug to fix.

T-2 — Buffers are shared. Several columns can bind the same buffer object. A renderer MUST NOT mutate, clear, resize, or delete a buffer. Only DataStore and relayoutByDepth() may.

T-3 — Blank traces with a perfectly healthy socket. Only the buffers a visible column needs are fed (dataStore.appendPacked / appendInterleaved). Any change to currentStreamId, selectedColKey or tracesPerColumn MUST call window.onLiveFilterChange() before the next draw(). Ordering matters at rebuild too: refreshStreamSelectors() then updateAppendModes() (main.js:636-639).

T-4 — Two buffers per channel, not one. dataSeries (packed depth order) and dataSeriesInterleaved (electrode order 0L,1R,2L,3R…). selectedColKey === 'B' binds the interleaved one; L/R bind the packed one.

T-5 — Both x values of a min/max pair are the same timestamp. Renderers that dedupe or assume strictly increasing x will erase the vertical extent of every bin.

T-6 — Plot geometry is unreadable before layout. seriesViewRect throws Cannot get seriesViewRect before layout has ocurred, and the old guard swallowed it, leaving every label slightly low. Read it only from the post-render hook, and never write a reactive property unconditionally there.

T-7 — draw() loops i < TRACES but positions with shownSlots. For i >= shownSlots the computed top exceeds 100 %; harmless only because those labels are display:none and their series invisible. Preserve both.

T-8 — Label DOM order is top-first. Index 0 = shallowest = slot topRange. Slot 0 is the tip and sits at the bottom. If depth appears upside-down, flip the range/slot sign in draw()/relayoutByDepth(), not the axis.

T-9 — Labels are placed arithmetically. space-around only lands on slot centres while the labels fit; past ~30 rows free space goes negative and they bunch and drift off their traces (style.css:147-153). Do not "simplify" back to flex.

T-10 — fitStrips() measures column 0 only, on purpose. flex:1 1 0 distributes in 1/64 px LayoutUnits while clientWidth rounds, so per-column measurement puts siblings on opposite sides of the threshold and produces two header heights in one row; and per-column class flips fire the chart ResizeObserver recursively (it took the page down during development). It also removes/restores strip-collapsed within one frame, and returns early on avail <= 0.

T-11 — Do not reintroduce @container shape tiers for the band (toolbar.css:723-740). Twelve tiers were deleted because the tier decided the shape and updateStripMode() then measured whatever shape the tier had chosen. The shape must not depend on the thing being measured.

T-12 — The collapsed band is position:absolute on purpose. In flow, revealing it resizes the chart and the ResizeObserver repaints on every hover. It also keeps the narrow 3-row template, because #view-data is overflow:hidden and a 448 px overlay in a narrow column loses ~275 px of controls.

T-13 — Stale drag handlers (a real defect; fix it). label.onmousedown and cursor:'grab' are assigned only in the probe-electrode branch and never cleared in the REF / ADC / plain branches (ChartColumn.js:729-756). Labels are reused across draws, so scrolling a probe label into a REF slot, or switching a column from a probe to the ADC, leaves a drag handler bound with the previous channel's electrode captured in its closure.

T-14 — draw() is the sole owner of shank/side visibility. refreshFilterOptions() used to set it and caused a visible flash, because its test (hasOrdering()) is weaker than draw's (hasOrdering() && channels.length === 384). refreshFilterOptions() also early-returns with no ordering, so stale shank options can survive a source change.

T-15 — isProbeStream() is channels.length === 384, by count, never by name. isVoltsStream() is a hardcoded currentStreamId === 'adc'. Any future 384-wide non-probe stream silently gets probe scaling; any 383-channel probe silently gets the volts-per-row clamp.

T-16 — bottomSlot is a slot index, not a channel id. slider.min/max set in buildHTML and in setTracesPerColumn are transient; draw() overwrites them from the band bounds every time.

T-17 — chSelector.value = String(tracesPerColumn) falls back to '' (Ch:Auto) for any count not in the option list — e.g. a __tracesOverride of 30 from a benchmark.

T-18 — Pin state does not survive a rebuild. buildColumns() destroys every instance; AppController.pinnedColumns is the only thing that outlives them.

T-19 — setTracesPerColumn keeps the surface and recreates only series + labels. destroy() MUST unbind every series before releasing the surface.

T-20 — Inline styles beat the stylesheet in two places. .channel-slider-container reads 60px in CSS but is inline 30px (deliberate — 27 px per column back to the traces); .vertical-slider reads 80 % but is inline 100 %.

T-21 — Sentinel zeros look like signal. An empty timebin writes 0.0f for min and max (DisplayProcessor.cpp:460-470), so a stalled band draws a flat line at its yOffset, not a gap. This is exactly the healthy-looking-dead-probe failure CLAUDE.md warns about. Count binary frames at the socket, not pixels.

T-22 — The first frame of every new stream is discarded (NetworkClient.js:82-85), and it is dropped again if no column exists yet (main.js:646). Stream allocation is lazy and frame-triggered.

T-23 — forceXAxisUpdate() runs per batch per stream, not per animation frame (main.js:746-758) — ~600 range writes/s plus ~150 textContent writes/s on a 3-stream config. This is a renderer-independent defect; fix it, or it gets miscredited to the renderer swap.

T-24 — µV is U+00B5 MICRO SIGN. Writing uV produced four false failures against a correct application (tests/gui/stream_options.py:34-36).

T-25 — Header height is DEFINITE (height: 46px), never min-height. min-height lets a column with more controls grow and puts the charts on different baselines.

T-26 — The theme is implicit. Passing any theme to the surface — or copying ImroManager.js:267-271's SciChartJsNavyTheme with a transparent background — silently repaints every column. Gridlines are off at the axis, not by theme: the theme still carries majorGridLineBrush #AAAAAA37 and axisBandsFill #20212333.

T-27 — Editing webinterface/*.js needs no build. CMakeLists.txt:248-292 removed the copy targets on 2026-08-26 and src/main.cpp:57-60 serves the directory off disk per request. developer_docs/NextTask_WasmFrontend.md:195-201 is wrong about this. But src/main.cpp:57 never strips the query string, and ? is an illegal Windows filename character — so a ?renderer=… A/B flag 404s until that one line is fixed.

T-28 — Rig and teardown rules apply (CLAUDE.md): always --no-browser; kill only the isolated debug-port Chrome profile you launched, never a blanket Get-Process chrome | Stop-Process; bring the backend down when not actively measuring, because a live backend holds bin/SpikesPeak.exe and the next build dies on LNK1104 — and the tempting fix is a kill, which is forbidden with a OneBox open.
