Archive — retired task briefs and superseded status snapshots#

Documents here are historical. They were accurate when written and are kept so a collaborator (or a new agent) can reconstruct why a decision was made — but they are not maintained and may contradict the current code. For anything current, read ../README.md and the live topic docs.

These files appear in the generated docs book under its own trailing "Archive (historical)" section, so you can read the history in the HTML site without it competing with the live docs in the nav. Archiving a file therefore demotes it rather than hiding it.

How to catch up (recommended order for a returning collaborator)#

  1. ../../SpikesPeak_Status.md → "Session index" — the dated, topic-tagged log of everything that happened, newest last. This is the single source of truth for what happened when. Start here.
  2. ../README.md — the current doc map + the START HERE agent path.
  3. This folder — only if you need the detail behind a specific retired item. Each entry below says what superseded it, so you can usually skip straight to the live doc.
  4. git log --follow developer_docs/archive/<file> — the change history of an archived file survives the move (it was git mv'd), so you can see when each claim was added.

To see what changed in the docs between two points in time:

git log --oneline --since="2026-07-09" -- developer_docs/ SpikesPeak_Status.md
git diff <old-sha>..HEAD -- developer_docs/          # what the docs say now vs then

Archiving policy#

  • NextTask_*.md is a transient brief. When the task lands, git mv it here in the same commit, fold anything durable into the topic doc, and add a row above.
  • Status snapshots (*_Status.md scoped to one effort) get archived once their content is merged into SpikesPeak_Status.md. The one exception is the top-level SpikesPeak_Status.md itself, which is the permanent running log.
  • Never archive a living reference doc (e.g. Neuropixels2.0.md, SimDataLinux.md, NiDaq.md) just because it is old — those are subsystem references, not snapshots.
  • Always add the row above, with what superseded it. An archive without that column is just a junk drawer.
