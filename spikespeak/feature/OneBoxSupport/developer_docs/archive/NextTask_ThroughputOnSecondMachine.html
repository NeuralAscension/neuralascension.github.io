Reproducing the recording throughput shortfall on the second machine#

Issue: #63. Read that first — it has the original numbers and the two effects they separate into.

Also read, in this order, because each one will otherwise cost you time:

Issue Why you need it
#63 The measurement itself. This page is its runbook.
#64 An unrecognised WebSocket command is silently ignored. This is what ruined the first attempt.
#51 Source switching. Not implicated here — I wrongly blamed it and retracted; do not go chasing it.
#52 The second-machine bring-up this was found during.
#53 Where the finding originally lived, in comments, before it was split out.

What is being asked#

On the second machine, OneBox recordings came out short and nothing warned:

run config band rec/s nominal %
A, t+15 s with ADC raw 23,429 30,000 78.1 %
A, t+15 s no ADC raw 29,997 30,000 99.99 %
B, t+90 s with ADC raw 19,980 30,000 66.6 %
B, t+90 s no ADC raw 19,740 30,000 65.8 %

Two independent effects: the ADC stream appears to cost ~22 % of probe throughput, and there is a decay to ~66 % by t+90 s that happens with the ADC disabled too.

The same four cells were run on the original rig on 2026-08-25 and every one recorded at 100.0 %. So the question this run answers is narrow and worth answering: is this machine, or its environment, different — and in what way?

1. Before you start#

git pull                          # you need Npx2OneBoxNoAdc.yaml, committed 2026-08-25
cmake --build build-Desktop_Qt_6_7_3_MSVC2019_64bit-Release

Npx2OneBoxNoAdc.yaml is the control. It is a copy of Npx2OneBox.yaml with every adc output, input and recording removed — the absence of a *.adc output is what disables the stream, so deleting only the recording would still pay the streaming cost and measure nothing.

Its internal name — which is what you select, not the filename — is NPX 2.0 Multishank (OneBox, no ADC).

Confirm the build deployed it:

ls build-Desktop_Qt_6_7_3_MSVC2019_64bit-Release/config/Npx2OneBoxNoAdc.yaml

2. The trap that ruined the first attempt — read this before scripting anything#

The WebSocket disconnect command is Disconnect, capital D, and it requires a value field:

ws.send_text(json.dumps({"command": "Disconnect", "value": True}))     # correct
ws.send_text(json.dumps({"command": "disconnect"}))                    # matches NOTHING, silently

There is no terminal else in the command handler, so a wrong name produces no warning, no log line and no reply (#64). On the original rig this meant the source was never released, the backend correctly refused every profile switch, and all four cells ran under the first profile — the control arm silently did not exist, and the files looked perfectly normal afterwards.

Two ways to avoid it. Either is fine:

  • Restart the backend between profiles. Simplest, and almost certainly what the original run did — its two arms read differently, so its switch genuinely took effect.
  • Switch live, and verify. Send setPlaying:false, then {"command":"Disconnect","value":true}, then selectSource, then read back the confirmed source name and refuse to record if it is not the one you asked for.

Either way, watch output.log in the backend's working directory while you run. A refused switch says so plainly:

[MainController]  Error: You must disconnect from a source before attempting to set a new one
[WebSocketServer] select "..." REFUSED -- "..." is still connected; state restored

If you see that line, the cell you just recorded is worthless. Stop and fix the script.

3. The four cells#

Ten seconds of recording each. Warm-up is measured from when streaming starts, not from launch.

cell profile record at
A_withadc_t15 NPX 2.0 Multishank (OneBox) t+15 s
A_noadc_t15 NPX 2.0 Multishank (OneBox, no ADC) t+15 s
B_withadc_t90 NPX 2.0 Multishank (OneBox) t+90 s
B_noadc_t90 NPX 2.0 Multishank (OneBox, no ADC) t+90 s

The harness used on the original rig is in the session scratchpad rather than the repo, because it carried the bug above. Write a fresh one, or drive it by hand from python python/spikespeak_cli.py, which already sends the correct command spellings:

python python/spikespeak_cli.py --script "select 'NPX 2.0 Multishank (OneBox)'; waitready 40; play; sleep 15; record <dir> A_withadc_t15; sleep 10; stop; sleep 2; pause; disconnect"

4. Counting — do not use a wall clock#

A script that times its own record / stop round trip is measuring its own latency and calling it data loss. Count from the files:

records = os.path.getsize(bin_path) // sidecar["frame"]["bytes"]
percent = 100.0 * (records / RECORD_SECONDS) / sidecar["sample_rate_hz"]

frame.bytes is declared in the sidecar — do not hardcode it. For the probe's raw band with three recorded channels it is 12 bytes ([uint32 timestamp][uint16 sync][int16 × 3]); for the 12-channel ADC band it is 30.

Cross-check the record's own duration against the sidecar's rate as well: both bands being short by the same fraction points at a shared cause rather than anything band-specific.

5. What to report#

  • The four percentages, and whether either effect appears.
  • If it reproduces: the two machines' differences, because the code is now known to be innocent — disk (model, free space, whether it is the same drive as the build tree), USB controller and whether the OneBox is on a hub, Windows power profile, and what else is resident.
  • If it does not reproduce: say so plainly, and note anything that changed on that machine since 2026-08-21. A fault that has gone away is still worth a line in #63.
  • Whether output.log shows any WARN or CRITICAL during a short run. The original observation was that it shows none, which is half of why the fault is dangerous.

6. Do not#

  • Do not force-kill the backend with the OneBox connected. The FT601 handle is released only on a clean exit and a kill costs a physical power-cycle. Use Disconnect, then quit.
  • Do not change Npx2OneBox.yaml to "test something quickly". The two profiles must differ in one variable, which is why the control is committed rather than edited in place.
  • Do not conclude anything from a cell where the source switch was refused.
