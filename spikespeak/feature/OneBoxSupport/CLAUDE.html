SpikesPeak — instructions for agents#

Qt/C++ acquisition backend + an external browser GUI (HTTP :8234, WebSocket :1234), Neuropixels 1.0/2.0 over PXIe or OneBox, online ripple detection, closed-loop stimulation.

Read developer_docs/README.md first — it is the map. This file is only the rules that are easy to get wrong and expensive when you do.

THE DEFINITION OF GREEN#

Do not report a build as working, passing, or green until BOTH suites pass. A compile that produced a binary is not a green build.

cmake --build build-Desktop_Qt_6_7_3_MSVC2019_64bit-Release

Runs the C++ suite automatically and prints a per-suite ✅/❌ banner. ~1.6 s, 316 cases.

python scripts/run_gui_tests.py

Runs the GUI suite. ~5 min. It is NOT part of the compile (it needs a browser and a backend), so you have to run it yourself — and you must run it whenever you touch webinterface/, the toolbar, the live view, the ripple dock, or anything an operator clicks.

A failing C++ suite does not stop the build by default (you usually still want the binary to debug with). That means a red suite is easy to walk past. Do not. -DSPIKESPEAK_TESTS_FATAL=ON makes red fatal; --fatal does the same for the GUI runner.

Full detail, including how to add a test and how to debug a failure: developer_docs/Testing.md.

Before you hand back#

  • [ ] cmake --build … → ALL N SUITES PASSED
  • [ ] python scripts/run_gui_tests.py → ALL N GUI TESTS PASSED
  • [ ] If you added a test, you proved it can fail — inject a regression, watch it go red, revert. An always-green test is worthless and worse than none, because it buys false confidence.
  • [ ] Nothing left running: no SpikesPeak.exe, no stray browser, ports 1234/8234 free.

Running the app#

run_spikespeak.bat --no-browser

Always pass --no-browser for automated work. Without it main.cpp calls QDesktopServices::openUrl and opens a window in the operator's default browser — on top of whatever browser you drove yourself. That is how a test run ends up with two GUIs on screen.

The launcher exists because the app needs Qt + Neuropixels + HDF5 on PATH; running the exe directly exits 0xC0000135. The backend auto-quits ~2 s after the last WebSocket client disconnects.

Hardware safety — read before touching a rig#

  • Never force-kill the backend while a real probe or OneBox is connected. The FT601 USB handle is released only on a clean exit; a kill costs a physical power-cycle. Shut down via the WebSocket quit command or the GUI's Disconnect. Since 2026-08-21 every teardown vendor call is bounded, so a wedged basestation no longer hangs shutdown — but the rule stands.
  • Do not leave a rig streaming while you do unrelated work (code, plots, docs). Pause and disconnect as soon as you move on. Long idle streams have stalled the NI-DAQ.
  • Do not leave the rig or a browser running for the operator to look at. Shut everything down and report with saved screenshots.
  • Killing browsers: kill only the isolated debug-port profile you launched. A blanket Get-Process chrome | Stop-Process closes the operator's real windows.

Sim first, always#

Every simulated source drives the same display processor, the same ring buffers, the same WebSocket and the same GUI as real hardware. So when something looks broken:

  1. Run the simulated source. If sim streams and hardware does not, it is the rig, not the code — and you have just saved yourself hours.
  2. Count binary frames at the socket, not pixels on screen.
  3. Ask what the counters actually count. (Source liveness means data committed; processor liveness means the loop turned. They are different on purpose.)

This is written up properly in developer_docs/Testing.md §4, with the 2026-08-20 incident that produced it: a dead probe reported a completely healthy rig for three and a half minutes.

Repo conventions#

  • SpikesPeak_Status.md is the canonical dated log. Not a todo file, not per-effort status files.
  • Finished briefs go to developer_docs/archive/.
  • Never commit recording-test data. Referenced analysis figures stay; the .bins never do.
  • No scratch files in the repo. Logs, captures and working files go to the session scratchpad.
  • Regenerate the docs book with python scripts/build_docs.py.
  • A config's identity is its internal name: field, not its filename.
  • Do not git add, commit or push unless the operator asks.
