The Documentation Book (HTML)#

The Markdown files in this repository are the single source of truth for the docs. A small generator, scripts/build_docs.py, compiles them into a browsable, self-contained HTML "book" under docs_site/ — with a dark/light theme, a left nav, a per-page table of contents, the Neural Ascension logo, and fully offline browsing. This page explains how to add, edit, and regenerate the docs, for both future agents and developers.

TL;DR#

# edit or add any .md file (see "Adding a document"), then regenerate:
python scripts/build_docs.py            # only dependency: pip install markdown
# open the result:
docs_site/index.html

The one dependency is the markdown package (pip install markdown). Any Python 3 works — python scripts/build_docs.py on Windows, python3 on Linux. A conda sp env is optional; if you have it, conda run -n sp python scripts/build_docs.py works too, but it is not required.

Never hand-edit anything in docs_site/ — it is generated (and git-ignored). Edit the .md sources (and scripts/docs_style.css for styling) and re-run the generator.

Where everything lives#

File / directory Role
scripts/build_docs.py the generator (discovery, HTML render, nav, link/image handling)
scripts/docs_style.css the theme — plain CSS with light/dark variables (edit freely)
docs_site/ generated output (git-ignored; open docs_site/index.html)
images/architecture.txt, images/plantuml_export.txt PlantUML diagram sources
images/architecture_overview.md narrative + the diagram SVG placeholders
webinterface/logo.svg the Neural Ascension logo (topbar + watermark; copied into the book)

Prerequisites#

The generator needs Python with the markdown package. The repo's sp conda env already has it, so the canonical command is:

conda run -n sp python scripts/build_docs.py

Otherwise install it with pip install markdown (no other dependencies, and no network is needed to view the generated output).

Adding a document#

  1. Create a .md file in one of the included directories: the repo root, user_docs/, developer_docs/, images/, or python/.
  2. Re-run the generator. The page appears automatically in the left nav (grouped by directory) and on the cover page.
  3. The page title shown in the nav is the file's first # H1 (it falls back to the filename).
  4. To control ordering within a section, add the filename to the PRIORITY dict in build_docs.py (lower number sorts earlier; unlisted files sort alphabetically after).

Included vs excluded content#

  • Included (top-level .md only, per directory) — the INCLUDE_DIRS list: ["", "user_docs", "developer_docs", "images", "python"] ("" is the repo root).
  • Excluded: third-party trees (ext/, Source-OpenEphys*, bin/), build-*, node_modules, docs_site/ itself, and the Open-Ephys nidaq-plugin/ reference.
  • To add a new section/directory: append it to INCLUDE_DIRS and add a ("<dir>", "<Section Title>") entry to the SECTIONS list (which also sets the nav order).

Cross-linking between documents#

Use ordinary Markdown links to the .md file — the generator rewrites .md → .html and keeps relative paths (the output mirrors the repo layout):

See [Ripple detection](../developer_docs/RippleDetection.html) for the algorithm.

External http(s):// links and in-page #anchors are left untouched. Note: the [`some/path.md`] style (square brackets around inline code, with no (url)) is not a link — it renders as literal code, on purpose.

Images#

  • Put image files under images/, user_docs/images/, or developer_docs/images/ (these trees are copied into the book, preserving their structure).
  • Reference them relatively from the doc, e.g. ![A caption](images/ripple/np2_detecting.png).
  • Supported extensions: png, svg, jpg, jpeg, gif, webp, ico.

Architecture diagrams (PlantUML)#

  • Sources: images/architecture.txt (high-level data/command flow) and images/plantuml_export.txt (detailed class diagram). Edit these text files to update the architecture as the code evolves.
  • Render them to SVG — paste into planttext.com, or run plantuml -tsvg images/architecture.txt images/plantuml_export.txt — and drop the resulting architecture.svg + plantuml_export.svg into images/.
  • images/architecture_overview.md already contains the ![...](architecture.svg) placeholders; once the SVGs exist and you re-run the generator, they render on the Architecture page (and copy into the book, since .svg is a supported image type).

Theme and styling (dark / light)#

  • The book has a theme toggle (☾ / ☀, top-right). It persists per-browser (localStorage) and respects the OS prefers-color-scheme on first load, applied before paint (no flash of the wrong theme).
  • All styling is in scripts/docs_style.css — plain CSS. The palette is CSS variables at the top:
  • :root { ... } = the light theme; html[data-theme="dark"] { ... } = the dark theme.
  • Rebrand by editing --brand (and the related color variables) in both blocks.
  • To change the default theme, edit the data-theme="light" value in build_docs.py's PAGE template (<html lang="en" data-theme="light">).

The logo watermark#

  • Source: webinterface/logo.svg — the same logo used as the main-UI background. build_docs.py copies it to docs_site/assets/logo.svg on every build, so updating the UI logo updates the docs too.
  • It appears in three places: the topbar (small icon), the cover (hero), and a very faint fixed background watermark on every page.
  • Adjust the watermark faintness via the body::before { ... opacity: ... } rules in docs_style.css (there is a separate light-mode override). The logo is white, so light mode inverts it (filter: invert(1)).

How the generator works (for agents modifying it)#

  • discover() collects the .md files. Each is rendered with python-markdown (extensions: extra, toc, sane_lists, admonition, meta) into an HTML body plus a per-page table of contents.
  • Each page is wrapped in the PAGE HTML template — placeholders %%TITLE%%, %%SECTION%%, %%NAV%%, %%BODY%%, %%TOC%%, %%LOGO%%, %%CSS%%, %%HOME%%, developer_docs/BuildingTheDocs.md — filled by render(). The stylesheet (STYLE) is read from scripts/docs_style.css.
  • The output mirrors the repo layout under docs_site/, so cross-doc links and relative images resolve offline (open the .html files directly, no server required).
  • Every run is a clean rebuild: the script deletes docs_site/ and regenerates it from scratch.

Do / Don't#

  • DO edit the .md sources; DON'T edit anything in docs_site/ (it is regenerated and git-ignored).
  • DO re-run the generator after any change to a .md file, docs_style.css, the logo, or the diagrams.
  • DON'T add third-party or vendored docs (e.g. ext/, nidaq-plugin/) to INCLUDE_DIRS.

Regenerate / preview#

conda run -n sp python scripts/build_docs.py        # regenerate docs_site/

Then open docs_site/index.html directly, or serve the folder for a nicer experience:

python -m http.server -d docs_site 8000             # then browse http://localhost:8000
