Using agy (Antigravity / Gemini) on SpikesPeak#

A SpikesPeak-specific companion to the plugin's own guide (~/.claude/plugins/cache/antigravity-for-claude-code/.../skills/antigravity/SKILL.md — read it for the full model). This file adds what's true on THIS repo + THIS machine, the verified command patterns, and — most importantly — how to actually verify agy's output here (agy can't run our GUI or measure frame rates; Claude must).

The one-line model#

Claude conducts, agy (a cheaper/faster second model) executes; Claude verifies EVERYTHING. Route deterministic, high-volume, or search work to agy; keep architecture, the hard 20%, and correctness on Claude. agy's self-reported "done/GREEN" is a claim, not evidence — it has been seen editing its own environment to force a pass. Never ship agy output you haven't independently checked.

This machine (verified 2026-07-12)#

  • agy v1.1.1 installed at ~/AppData/Local/agy/bin/agy; wrappers agy-delegate / agy-job on PATH from the plugin cache. agy models lists what your account can route to — here: Gemini 3.5 Flash (Low/Med/High), Gemini 3.1 Pro (Low/High), Claude Sonnet 4.6 (Thinking), Claude Opus 4.6 (Thinking), GPT-OSS 120B.
  • Native Windows + git-bash works despite the plugin's general "avoid native Windows (ConPTY hang)" caveat — two delegations (a web-search research call and an Opus code-gen call) both completed cleanly this session. The wrapper's wall-clock timeout guards the hang. Two agy delegations ran concurrently without a problem.
  • Model choice: --tier flash (Gemini) for bulk/search; --model "Gemini 3.1 Pro (High)" for reviews; --model "Claude Opus 4.6 (Thinking)" for an intricate, correctness-critical refactor where you want a strong executor (still verify it). Keep the executor a different model from the Claude conductor for the cross-model check + the cost win.

When to delegate on SpikesPeak (and when NOT)#

Delegate (above break-even): - Web / deep research — hardware datasheets, vendor-API behavior, browser/library capabilities. agy has Google search; Claude does not. Always --digest, and re-verify load-bearing claims. - Bulk, well-specified code — exhaustive test/eval generation, a mechanical migration across many files, scaffolding a new module from a spec Claude wrote. - Long-context reads that distill to a digest — "summarize how X works across these 12 files → digest".

Do NOT delegate (do it yourself): - Small one-off edits, renames, single-function tweaks (delegation overhead > the work). - Judgment/architecture-bearing changes — unless you hand agy a very tight spec AND verify hard. (This session's Option A worker refactor was delegated to Opus with a 5.7 KB spec, precisely because the integration is delicate — and it was verified line-by-line + in the GUI afterward.) - Anything touching the C++ backend / real hardware paths — keep those on Claude.

Proven command patterns (from this repo's history)#

1. Web-search research → digest (read-only; --yolo enables the web tool):

agy-delegate --yolo --digest --timeout 8m 'Research <X> with web search. Answer <specific questions>.
  Cite official-source URLs. If something is NOT supported, say so. End with a ===DIGEST=== block.'

Used this session for "SciChart.js multithreading options" (found: no OffscreenCanvas worker support, no pthreads WASM, SubCharts API exists) and "how agy is used here". Ingest the DIGEST only.

2. Code generation from a tight spec → file edits (write task; --mode accept-edits = file edits only, no terminal grant — safer than --yolo):

# Put the spec in a file (Bash heredocs here cap ~5 KB per command; write big specs in chunks or a file),
# then pipe it so you dodge the arg-length limit:
agy-delegate --model "Claude Opus 4.6 (Thinking)" --mode accept-edits \
  --dir "C:/Users/BIOEl/Documents/Code/SpikesPeak" --timeout 15m - < /tmp/spec.txt

Used this session for the Option A "transform worker" refactor. Always pass --dir <repo-root> so agy reads the real files (and AGENTS.md if present) instead of pasted code. Run in the background (run_in_background) in an interactive session so you're not blocked; you'll be notified on completion.

Spec-writing tips that made agy's first pass good: state the exact design + message protocol, name the files + line ranges to read, list hard correctness constraints ("baked values must be bit-identical", "don't touch the control path"), demand a graceful fallback, and ask for a ===DIGEST=== of what changed.

VERIFYING agy's work on SpikesPeak (the part agy can't do)#

agy cannot launch our Qt backend, drive the browser, or measure frame rates — so Claude owns every verification. The loop that catches real bugs here (a static "looks right" review is NOT enough — a subtle data-binding slip silently blanked all the live traces this session and only a GUI run caught it):

  1. Diff review. Snapshot the target files first (cp … /tmp/agy_baseline/), then diff after — read agy's actual changes, not just its digest. Check for hallucinated APIs and broken invariants.
  2. Syntax check. JS: cp file.js /tmp/x.mjs && node --check /tmp/x.mjs. C: gcc -fsyntax-only isn't available for the Pi/ARM code on this box, so review + brace-balance instead.
  3. Deploy the pure-frontend changes to where the backend serves them: cp webinterface/* build-Desktop_Qt_6_7_3_MSVC2019_64bit-Release/webinterface/ (no C++ rebuild for JS/HTML/CSS). For C++ changes, rebuild (vcvars64 + cmake --build …).
  4. Run it for real. python run_spikespeak.py --no-browser (or the exe with Qt/Neuropix/HDF5 on PATH) + an isolated Chrome on --remote-debugging-port=9222; drive via python/tools/cdp.py. Confirm live traces actually render (window.app.columns[i].onScreenSeries[0].dataSeries.count() > 0), not just that the layout drew.
  5. Measure. benchmarks/cdp_bench.py sweeps channel density and reads window.__perfStats + CDP Performance.getMetrics (fps, frame time, main-thread busy). Compare before/after; the numbers are the acceptance criterion, not agy's prose.
  6. Teardown kills ONLY the debug-port/isolated-profile Chrome + your SpikesPeak instance — never a blanket chrome kill (see the gui-browser-teardown memory).

Cost discipline (the savings are real only at scale)#

Delegation isn't free — below the break-even the hybrid costs more (Claude's cache_read on a growing context dominates). Hard rules: - Ingest a DIGEST, never a dump. End prompts with a ===DIGEST=== contract; the wrapper even warns on stderr when a reply is dump-sized (> ~8000 chars). Do not pull the files agy already handled back into Claude's context. - --dir over pasting (denser, cheaper context). - Batch one big, fully-specified delegation over many chatty round-trips (each round-trip re-taxes the cache). - --continue / --conversation <id> to hold multi-step state on the cheap Gemini side. - Don't manufacture "keep-warm" turns during a long delegation — measured to backfire. Backgrounding avoids blocking, not cost.

Gotchas on this box#

  • Bash heredoc ~5 KB limit (this Claude Code shell): write big agy specs to a file in chunks (cat >>), then agy-delegate … - < file.
  • --yolo vs --mode accept-edits: use accept-edits for pure file writes (narrower, safer); use --yolo only when the task needs the web tool / terminal (research, search). Without a write grant, headless agy may write to its own scratch dir and still report success — always confirm files changed in the workspace.
  • Structured exit codes: 10 quota (retry later, --continue) · 11 auth (agy once interactively) · 12 timeout (raise --timeout / narrow the task) · 13 agy missing · 2 failed · 3 empty output.
  • Trajectory is opaque in print mode (conversation history is binary SQLite). Ask agy to summarize its own steps in the reply, or use agy-trace <conversationId> for internal-subagent transcripts.
  • Native Windows works here, but if it ever hard-hangs with a 0-byte log, that's the ConPTY issue — the timeout guard will free you; WSL/Linux is the upstream-recommended host.
