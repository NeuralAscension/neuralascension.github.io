OpenEphys OneBox — reference digest (for the SpikesPeak OneBox port)#

Supporting reference for archive/NextTask_OneBoxSupport.md (that plan is the authority). This is a digest of how the OpenEphys neuropixels-pxi plugin implements OneBox, produced by Antigravity/Gemini and then cross-checked symbol-by-symbol against the vendored v4 header external/neuropixels/api/include/v4/NeuropixAPI.h. Every IMEC call named below exists in that header (confirmed): scanBS, getDeviceList, getDeviceInfo, basestationID.platformid, NPPlatform_USB/NPPlatform_PXI, mapBS/unmapBS, openBS/closeBS, checkFtdiDriver, ADC_readPackets, ADC_setVoltageRange, ADC_getStreamConversionFactor, ADC_enableProbe, ADC_setComparatorThreshold, DAC_setVoltage(s)/DAC_enableOutput, waveplayer_writeBuffer/ waveplayer_setSampleFrequency/waveplayer_arm/waveplayer_stop, setSWTrigger/setSWTriggerEx, switchmatrix_set/get/clear, openPort/detectHeadStage/arm. v3↔v4 OneBox surface: no regression (v4 is a superset).

Two SpikesPeak-specific corrections to keep in mind when reading below: 1. Streaming call — the digest says readPackets (OpenEphys' generic path). SpikesPeak's existing workers use np_readElectrodeData for NP1.0 (ap+lfp) and np_readPackets for NP2.0 (raw); we reuse those workers unchanged, so this nuance is already handled. 2. ADC counts→volts — prefer the API's ADC_getStreamConversionFactor(slot,&lsb_to_voltage,&bit_depth) over OpenEphys' hardcoded bitVolts constant.

A. OneBox device model & detection#

  • Detection vs PXI: OpenEphys triggers hardware detection using Neuropixels::scanBS(), retrieves the list with Neuropixels::getDeviceList(struct basestationID* list, int count), and examines each device with Neuropixels::getDeviceInfo(int slotID, struct basestationID* info). It distinguishes a OneBox from a PXI basestation by checking if info.platformid == Neuropixels::NPPlatform_USB (as opposed to Neuropixels::NPPlatform_PXI).
  • Slot numbering: OpenEphys uses a virtual slot number generator for OneBox devices, starting at 16 (const int first_available_slot = 16;). It binds the OneBox serial number to this virtual slot via Neuropixels::mapBS(int serial_number, int slotID).
  • Open/Close sequence: Opened via Neuropixels::openBS(int slotID) and closed via Neuropixels::closeBS(int slotID).
  • Connection/driver: OneBox is an FTDI USB device. OpenEphys validates the driver using Neuropixels::checkFtdiDriver(ftdi_driver_version_t* required, ftdi_driver_version_t* current, bool* is_driver_present, bool* is_version_ok).

B. Probe streaming via OneBox#

  • Difference from PXI: The API path for probe streaming is IDENTICAL to PXI. Neural data from a probe connected via OneBox is read using the exact same API calls (e.g. Neuropixels::readPackets). There is no API-level distinction between reading a probe on OneBox vs PXI once the base station is mapped to a slot and opened. OpenEphys reuses its existing probe-streaming worker.

C. OneBox ADC (analog input)#

  • Channels & Sample Rate: There are 12 channels (OpenEphys defines NUM_ADCS = 12). OpenEphys hardcodes the sample rate to 30300.5 Hz.
  • Reading: ADCs are read via Neuropixels::ADC_readPackets(int slotID, struct PacketInfo* pck_info, int16_t* data, int channel_count, int packet_count, int* packets_read).
  • Data type/scale: The data returned is int16_t signed integers. OpenEphys scales these to volts using a bitVolts multiplier that depends on the configured voltage range (e.g., 5.0f / float(pow(2, 15)) for the ADC_RANGE_5V setting).
  • Configuration: Voltage range is set via Neuropixels::ADC_setVoltageRange(int slotID, ADCrange_t range). The probe must be enabled with Neuropixels::ADC_enableProbe(int slotID, bool enable).
  • Hierarchy: OneBoxADC does not derive from Probe. It derives from DataSource.

D. OneBox DAC / waveplayer (analog output) + digital I/O + SMA#

  • DAC Output: Can be enabled/disabled per channel using Neuropixels::DAC_enableOutput(int slotID, int DAC_channel, bool state).
  • Waveplayer Setup:
  • Sample frequency set via Neuropixels::waveplayer_setSampleFrequency(int slotID, double frequency_Hz).
  • Buffer written via Neuropixels::waveplayer_writeBuffer(int slotID, const int16_t* data, unsigned int len).
  • Armed for playback via Neuropixels::waveplayer_arm(int slotID, bool single_shot).
  • Digital I/O: Digital states are captured through ADC comparators. The thresholds are configured using Neuropixels::ADC_setComparatorThreshold(int slotID, int ADC_channel, double v_low, double v_high).
  • Triggers: The waveplayer is triggered in OpenEphys by sending software trigger 2: Neuropixels::setSWTriggerEx(int slotID, swtriggerflags_t trigger_flags) using Neuropixels::swtrigger2.

E. Switch matrix / trigger routing on OneBox#

  • At Open Time: Configures sync as an input by clearing current routes via Neuropixels::switchmatrix_clear(int slotID, switchmatrixoutput_t output) for Neuropixels::SM_Output_StatusBit and Neuropixels::SM_Output_SMA, and linking them to Neuropixels::SM_Input_SMA using Neuropixels::switchmatrix_set(int slotID, switchmatrixoutput_t output, switchmatrixinput_t input, bool connect).
  • At Acquisition Time: Maps the acquisition trigger to software trigger 1 using Neuropixels::switchmatrix_set(int slotID, Neuropixels::SM_Output_AcquisitionTrigger, Neuropixels::SM_Input_SWTrigger1, true).

F. UI surface#

  • The OneBoxInterface UI class exposes the following user-configurable parameters:
  • ADC input range (+/- 2.5 V, +/- 5 V, +/- 10 V)
  • Use as digital input (Comparator ON/OFF, per channel)
  • Trigger WavePlayer (Boolean mapping, per channel)
  • (Note: DAC channel mapping is partially written but currently commented out in the OpenEphys UI).

G. A concrete minimum-viable OneBox source call sequence#

Main sequence to detect, configure, and stream from a probe: 1. Neuropixels::scanBS() 2. Neuropixels::getDeviceList(struct basestationID* list, int count) 3. Neuropixels::getDeviceInfo(int slotID, struct basestationID* info) -> Verify info.platformid == Neuropixels::NPPlatform_USB 4. Neuropixels::mapBS(int serial_number, int slotID) -> Map to virtual slot (e.g., 16) 5. Neuropixels::openBS(int slotID) 6. Neuropixels::detectHeadStage(int slotID, int portID, bool* detected) 7. Configure base station routes: Neuropixels::switchmatrix_set(slotID, Neuropixels::SM_Output_AcquisitionTrigger, Neuropixels::SM_Input_SWTrigger1, true) 8. Arm device: Neuropixels::arm(int slotID) 9. Trigger device: Neuropixels::setSWTrigger(int slotID) 10. Loop: Neuropixels::readPackets(int slotID, ...) (Standard probe stream) 11. Stop: Neuropixels::arm(int slotID) (OpenEphys uses arm to stop acquisition without triggering) 12. Neuropixels::closeProbe(...) 13. Neuropixels::closeBS(int slotID)

Minimal call sequence to read the ADC stream: 1. Neuropixels::ADC_enableProbe(int slotID, bool enable) (set to true) 2. Neuropixels::ADC_setVoltageRange(int slotID, ADCrange_t range) 3. Loop: Neuropixels::ADC_readPackets(int slotID, struct PacketInfo* pck_info, int16_t* data, int channel_count, int packet_count, int* packets_read)

H. Gaps/mismatches#

  • API Skew: There are no apparent missing functions or renames referenced by OpenEphys compared to the vendored v4 header. All calls conform exactly to the v4 API signatures.
  • Framework Dependencies: OpenEphys heavily relies on its internal JUCE framework objects for implementation (Array, String, OwnedArray, ComboBox, DynamicObject, XmlElement, MessageManager, Thread, etc.) to handle threading and buffering. SpikesPeak will need to adapt these into standard Qt C++ components.

Context for next step: The architecture of OneBox in the API relies completely on mapping the physical USB hardware to a virtual slot (e.g., 16), after which standard probe initialization and neural data acquisition functions (readPackets) proceed exactly as they do for PXI. The main differences are discovering the platform, mapping it manually to a slot, checking the FTDI driver, and handling the OneBox's dedicated ADC/DAC functionality which is managed by a distinct DataSource object rather than a standard Probe. The next step for writing the implementation plan will involve mimicking the virtual slot assignment and updating SpikesPeak's device detection to accommodate NPPlatform_USB, as well as adapting the ADC background thread using Qt constructs.
