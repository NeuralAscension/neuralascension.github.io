"Recording Test" — runbook for agents#

When the user asks for a "Recording Test", this is the exact, headless, hardware-driven end-to-end check to run and what they are looking for. It drives the live NPX 1.0 + NI-DAQ hardware on this machine via the control CLI (no GUI clicking), records a short clip, and produces two eyeball plots.

⚠️ NP2.0: everything below is Neuropixels 1.0-specific and MUST be updated for the NP2.0 multishank probe — see § NP2.0 multishank variant at the bottom.

🐧 Platform: this runbook targets the Windows hardware box (real NPX 1.0 + NI-DAQ). Dev has moved to a Linux box with no hardware (2026-07-06). The equivalent hardware-free test uses the simulated NP1.0 source — this is DONE (SimDataLinux.md); see the Linux / simulated variant below.

Linux: simulated NP1.0 variant (no hardware)#

On the Linux/sim box the SAME CLI flow works against the simulated source — no NI-DAQ, no probe.

  1. Python env: use conda base (source ~/anaconda3/bin/activate base) — the system python lacks pip/matplotlib. pip install -e python once so plot_recording.py can import spikespeak_postprocess.
  2. Launch headless (offscreen platform — WebEngineWidgets needs a plugin and there's no display): bash cd build/Desktop_Qt_6_11_1_Release # the Qt Creator build dir on this box LD_LIBRARY_PATH=~/Qt/6.11.1/gcc_64/lib QT_QPA_PLATFORM=offscreen \ ./bin/SpikesPeak --no-browser &
  3. Drive the recording (keep < 30 s; consecutive testN under bin/RecordingTests/; teardown stop → pause → disconnect → quit). Note the config is "Simulated Data" and there is no NI-DAQ: bash BIN=$PWD/bin python python/spikespeak_cli.py --host localhost --script \ "select 'Simulated Data'; waitready 40; probemap default; sleep 1; play; sleep 3; \ record $BIN/RecordingTests testN; sleep 8; stop; sleep 2; pause; sleep 2; disconnect; sleep 3; quit" waitready blocks on the backend's Found simulated Neuropixels 1.0 Probe. probemap bank1|bank2 also work (the sim publishes a real Bank-0 map + bank presets).
  4. Verify. python python/examples/plot_recording.py <rec> writes channels.png + sync.png. The synthetic signal is a clean sine, IDENTICAL on every channel (AP 10 Hz, LFP 4 Hz; ~250 µV σ AP / ~500 µV σ LFP) — it is purely software-generated, NOT a model of any real/damaged probe. The sync field is a clean ~1 Hz square pulse train; with no NI-DAQ band, plot_recording.py now plots the NPX sync train on its own (full + 2 s window + rising-edge zoom) instead of the NI-DAQ cross-alignment. For the ripple sim, select 'NPX 2.0 Synthetic Ripples' records the raw band AND fires the ripple detector (needs > ~7 s).

Prerequisites#

  • Hardware is physically connected; connecting a real config drives it — see [[hardware-connected-testing]].
  • Build is current. If you changed C++/JS, rebuild first (the [[spikespeak-build]] recipe); POST_BUILD deploys webinterface/, config/, imro_maps/ next to the exe.
  • Standalone launch needs C:\Qt\6.7.3\msvc2019_64\bin and external\neuropixels\api\lib64\v4 on PATH (HDF5 already on the system PATH). See ControlCLI.md.

Steps#

  1. Launch headless (no browser tab left open): powershell $bin = "...\build-Desktop_Qt_6_7_3_MSVC2019_64bit-Release\bin" $env:PATH = "C:\Qt\6.7.3\msvc2019_64\bin;...\external\neuropixels\api\lib64\v4;" + $env:PATH Start-Process -FilePath "$bin\SpikesPeak.exe" -WorkingDirectory $bin -ArgumentList "--no-browser" ` -RedirectStandardOutput "$bin\t_out.log" -RedirectStandardError "$bin\t_err.log" -WindowStyle Hidden # then poll TCP 1234 until listening
  2. Drive the recording via the CLI (keep each recording < 30 s; name it the next consecutive testN under <bin>\RecordingTests\). Correct teardown is stop → pause → disconnect → quit: bash python python/spikespeak_cli.py --script \ "select 'NPX 1.0 with NI-DAQ'; waitready 40; probemap default; sleep 2; play; sleep 3; \ record <bin>/RecordingTests testN; sleep 15; stop; sleep 2; pause; sleep 2; disconnect; sleep 3; quit" waitready blocks on the backend's Found Neuropixels 1.0 Probe status. For a bank test, swap probemap default for probemap bank1 / probemap bank2 (NP1 only).
  3. Plot + verify (writes sync.png + channels.png INTO the recording folder): bash python python/examples/plot_recording.py <bin>/RecordingTests/testN
  4. Clean up the temp t_out.log / t_err.log. Confirm the process exited (clean quit).

The config under test#

config/Npx1PxiNiDaq.yaml ("NPX 1.0 with NI-DAQ") records electrodes [1, 192, 196] (AP @30 kHz + LFP @2.5 kHz) and all 8 NI-DAQ channels @40 kHz. Electrodes 192 & 196 are deliberately chosen — their amplifiers read more variable (suspected damaged), so they're an easy visual signal. Edit the channels: lists to change what's recorded.

What the user is looking for#

  • channels.png — AP and LFP blocks for electrodes [1, 192, 196], per-band shared µV scale:
  • e1 should look clean/quiet; e192 / e196 visibly noisier (bigger σ / peak-to-peak, spiky artifacts). This is the "damaged amp" proof AND confirms both AP and LFP bands are recording.
  • sync.png — NI-DAQ↔NPX timestamp sync (a shared TTL pulse train on the NPX sync field + NI-DAQ ch0): 4 rows = full native, full aligned, and a rising-edge zoom pre-sync (both edges + the native offset, e.g. +3.94 ms) and post-sync (NPX + aligned NI-DAQ overlapping). Confirms the drift correction works (expect a few ppm, sub-ms residual). If there's no shared pulse train it still renders the raw signals with a "no drift fit" note.
  • Clean teardown — no hang; the probe is released (a mid-stream disconnect used to leave it bad).

Bank-test caveat (electrode vs read-out channel)#

The config channels: are electrode numbers assuming the default Bank 0 map (where electrode == read-out channel). A probemap bank1/bank2 changes which electrode each read-out channel carries, but the recorder still writes read-out channels 1, 192, 196. So under bank1/bank2 the same channels read different electrodes and the data changes (that change is the proof the bank reached hardware) — but the sidecar's electrode labels are still the Bank-0 numbers. Bank presets load imro_maps/npx1_bank{0,1,2}.imro; bank2 is a partial bank (ch 0–191 → bank 2, ch 192–383 → bank 1).

NP2.0 multishank variant (2026-07-06)#

NP2.0 multishank is now at parity (Status §15). The SAME CLI flow works; the key differences from 1.0:

  • Config / bands: NP2 is a SINGLE raw band (30 kHz), not ap/lfp. Use config/Npx2Pxi.yaml ("NPX 2.0 Multishank", now has a proc.npx.recorder + proc.lfp) or NpxPxiNiDaq.yaml for 2.0 + NI-DAQ. rec.bands() returns ['raw'] (+ ['nidaq']). The derived LFP comes from proc.lfp (not a recorded band).
  • No bank presets: probemap bank1|bank2 is (correctly) REJECTED for NP2. Use default (shank 0, Bank A) or an NP2 .imro path. In the GUI editor use the Shank dropdown + Bank A-D presets.
  • Readiness: the backend reports Found Neuropixels 2.0 Multishank Probe; waitready keys on "found … probe" so it still works.
  • Sync: the NPX sync field + spikespeak_postprocess.synchronize(reference_band="raw", …) carry over.

Hardware-free (simulated 2.0) — the readily-runnable check on ANY box:

BIN=<bin>   # the build's bin dir
python python/spikespeak_cli.py --host localhost --script \
 "select 'Simulated NPX 2.0 Multishank'; waitready 40; probemap default; sleep 1; play; sleep 3; \
  record $BIN/RecordingTests np2simN; sleep 8; stop; sleep 2; pause; sleep 2; disconnect; sleep 3; quit"

The raw .bin is a clean sine IDENTICAL on every channel (10 Hz + 4 Hz components; the 4 Hz shows up in the derived LFP), with a ~1 Hz sync square. select 'Simulated NPX 2.0 Multishank + NI-DAQ' also records the NI-DAQ band and rec.synchronize(reference_band="raw", nidaq_sync_channel=0) recovers the ~10 ppm drift. A headless-Chrome CDP smoke test of the 4-shank editor / record-selection / live view is cdp_np2_smoke.py.

Real 2.0 probe: select 'NPX 2.0 Multishank', then the same flow. Confirm the log shows writeProbeConfiguration VERIFIED OK on probemap default/Apply. Pick NP2 read-out channels for the channels: list (the default map is all shank 0).
