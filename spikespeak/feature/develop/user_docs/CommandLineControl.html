SpikesPeak — Command-Line & Console Control (User Guide)#

SpikesPeak normally opens a browser UI (see GUI-Guide.md). But you can also drive it entirely from the keyboard — no GUI — which is handy for automated tests, remote/headless rigs, or a quick poke without reaching for the mouse. There are two ways:

Way What it is Best for
① Console commands Type commands straight into the console window the backend runs in. Nothing else to install or run. A quick local connect / play / stop, right where the app is running.
② Python control CLI python/spikespeak_cli.py talks to the backend over its network port — the same channel the browser uses. Scriptable and remote-capable. Automation, recording, waiting for "ready", or controlling a backend on another machine.

This is the operator's guide. The exact commands, wire protocol, and internals are in ../developer_docs/ControlCLI.md.

① Command the backend from its console#

When SpikesPeak is running it prints a > prompt and accepts a small set of typed commands. This works whether or not the browser UI is open — the console is always listening as long as there's a real console.

Getting a console to type in - Windows — launch SpikesPeak.exe from a terminal (PowerShell / Command Prompt), or from Qt Creator. A console window is attached; click it and type. (Double-clicking the exe also opens a console window alongside the browser — you can type there too.) - Linux — type into the terminal you launched it from. - If you started it fully headless with stdin redirected (e.g. piped from a script), console commands are automatically disabled (it logs console commands disabled) — use the Python CLI (②) instead.

The commands (this is the complete set):

Type this What happens
connect <source name> Connect that source. Use the exact name shown in the GUI Source menu / config, e.g. connect Simulated Data or connect NPX 1.0 with NI-DAQ. No quotes; spaces are fine.
play Start streaming.
pause Pause streaming (keeps the source connected).
disconnect Release the source (pauses first automatically if still streaming).
quit (or exit) Shut the whole app down.

Anything else prints Unrecognized command; a blank line is ignored.

A console session looks like this (after each > command the backend prints a confirmation line):

> connect Simulated Data
[MainController] Source connected and not streaming
> play
Attempting to stream from source
[MainController] All sources have started
> pause
[MainController] Source paused
> disconnect
[MainController] Source disconnected and set to none
> quit
Shutdown initiated

Console limits: connect / play / pause / disconnect / quit only — there is no recording, no source listing, and no probe-map from the console, and you must know the source's exact name. For those, use the Python CLI below.

② The Python control CLI (spikespeak_cli.py)#

A tiny script that commands the backend over its WebSocket. No extra packages — plain Python 3. An open browser mirrors whatever the CLI does (the Source menu, ▶ Play, ⏺ Record all update live), so you can watch.

Step 1 — start the backend without a browser:

python run_spikespeak.py --no-browser        # add --offscreen on a machine with no display at all

Step 2 — command it. The commands:

Command What it does
list Print every available source (these names are what you pass to select / console connect).
select "<name>" Connect a source by name.
waitready [seconds] Wait until the source reports ready (better than guessing a sleep).
play / pause Start / pause streaming.
record <dir> <name> Record to <dir>/<name>/.
stop Stop recording (streaming continues).
probemap <default\|bank0\|bank1\|bank2\|file.imro> Set the Neuropixels channel map.
disconnect Disconnect the source.
quit Shut the backend down.
sleep <s> Wait (inside a script).

Run it three ways:

# interactive — type one command at a time; the server stays up until you quit
python python/spikespeak_cli.py

# one-shot — run a single command and exit (great for `list`)
python python/spikespeak_cli.py list

# scripted — a full sequence in one go (semicolons separate commands)
python python/spikespeak_cli.py --script "select 'Simulated Data'; waitready 40; play; sleep 5; pause; disconnect; quit"

Record a 10-second clip (no hardware — simulated source):

python python/spikespeak_cli.py --script \
  "select 'Simulated Data'; waitready 40; play; sleep 2; \
   record RecordingTests demo1; sleep 10; stop; pause; disconnect; quit"

The files land in RecordingTests/demo1/. (To look at them, see GUI-Guide.md or the developer doc.)

Control a backend on another machine (same network):

python python/spikespeak_cli.py --host 192.168.1.50 --port 1234 list

One important gotcha: the backend shuts itself down ~2 seconds after the last connection closes. A bare one-shot like list connects and then disconnects, which can end the session. For anything multi-step, put the whole thing in one --script (so a single connection stays open the whole time), or keep a browser open on the side to hold the server up.

Driving the Ripple Detection module from the CLI#

The Python CLI can also run the Ripple Detection module — the same thing the browser dock does (see RippleDetection.md for what the settings mean). play first, then:

Command What it does
ripple channels <e1> <e2> … Choose the detection electrodes.
ripple z <electrode> <value> A channel's sensitivity (z-score) — lower = more sensitive. Works live.
ripple param estimation_seconds <s> Baseline training time (use a few seconds for a quick test).
ripple param quorum_count <n> How many channels must fire together to count as a detection.
ripple start / ripple pause Begin / stop detecting (the first start trains first).
ripple retrain Re-learn the baselines.
ripple arm / ripple disarm Turn the stimulator on / off (works even when not streaming).
ripple stimserver <ip> Point the stimulator at a different server.
ripple testfire Send one test pulse.

A full ripple run (simulated — fires detections in ~10 s):

python python/spikespeak_cli.py --script \
  "select 'Latency Bench NP1 (baseline delivery)'; waitready 30; play; sleep 2; \
   ripple channels 0 10 20; ripple z 0 2; ripple z 10 2; ripple z 20 2; \
   ripple param estimation_seconds 3; ripple param quorum_count 2; \
   ripple start; sleep 18; ripple pause; disconnect; quit"

As it runs you'll see training progress and then detections like [ripple ● DETECTED] 2/3 ch [0, 10]. The full walkthrough of what these numbers mean (and tuning them) is in RippleDetection.md.

Tips & troubleshooting#

  • No > prompt / typing does nothing → there's no console attached. On Windows, launch the exe from a terminal; if you started it headless with redirected input, use the Python CLI instead.
  • Unrecognized command → the console only understands connect / play / pause / disconnect / quit. Use the Python CLI for record, list, probe maps, etc.
  • connect / select fails → the name must match exactly (spaces and capitalization count). Run python python/spikespeak_cli.py list to see the exact names.
  • The server quit between two commands → that's the auto-shutdown after the last client left. Use one --script, or keep a browser open.
  • Remote control can't connect → make sure the other machine's firewall allows port 1234.
