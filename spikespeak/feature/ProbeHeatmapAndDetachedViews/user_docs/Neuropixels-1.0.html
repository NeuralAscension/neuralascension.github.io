Using a Neuropixels 1.0 Probe#

A step-by-step walkthrough: connect a Neuropixels 1.0 probe, choose which electrodes record, push that map to the probe, and watch the live signal. For the toolbar reference, see README.md.

A 60-second primer on the 1.0 probe#

A Neuropixels 1.0 shank has 960 electrodes, but the probe can only read out 384 channels at once. So each of the 384 channels is wired to one electrode chosen from a fixed set:

  • The 960 electrodes are split into banks of 384: Bank 0 (deepest, electrodes 0–383), Bank 1 (middle, 384–767), Bank 2 (top — a half bank, electrodes 768–959, so it only covers channels 0–191).
  • Channel C can record electrode C, C+384, or C+768 (its bank choices). Picking one electrode for a channel automatically un-picks that channel's other banks.
  • The two columns of sites (left / right) and increasing depth down the shank are what the live view sorts by.
  • A few sites (191, 575, 959) are internal reference points, not recording electrodes — the editor shows them in amber and won't let you select them.

You don't have to memorize this — the editor enforces it. The point: you choose a 384-electrode "channel map," apply it to the probe, then stream.

1. Launch + connect#

  1. Run SpikesPeak.exe; the UI opens in your browser (see README).
  2. In the Source dropdown, pick Neuropixels — you name neither the basestation nor the probe; both are read from the rig. Pick PXIe with NI-DAQ instead if you also want the NI-DAQ card's analog and digital inputs (that entry appears only when a PXIe module is detected). There is no "NPX 1.0" entry, and no PXIe entry either unless a OneBox is attached at the same time and the scan has to ask. - 📷 Source dropdown
  3. Watch the status box (right side): Connecting to Neuropixels… → Found Neuropixels 1.0 probe / Connected — device ready (green). The Probe Map and Live Data tabs appear, and Play becomes available. - If it goes red, the probe wasn't found — check the PXI connection and the console window.

2. Probe Map vs Live Data#

Two tabs appear at the top: - Probe Map — configure which electrodes record (this section). - Live Data — watch the signal (§5).

You can configure the map first, apply it, then switch to Live Data and Play — or Play first and tune the map live (each Apply briefly pauses and restarts streaming automatically).

3. Configure the channel map (Probe Map tab)#

📷 Probe Map editor with the shank + electrode grid

The panel shows the shank with its electrodes: - Green = currently selected to record. Gray = available but not selected. Amber = internal-reference site (can't be selected).

Three ways to choose electrodes:

  1. Bank presets — the quickest start: - Bank 0 (Deep) — all 384 channels read their deepest electrodes (0–383). - Bank 1 (Middle) — electrodes 384–767. - Bank 2 (Top) — the half-bank: channels 0–191 jump to bank 2, channels 192–383 stay on bank 0.
  2. Click an electrode — routes that electrode's channel to that electrode's bank (its bank-siblings auto-deselect). Use this to hand-tune individual channels.
  3. Drag a vertical box — assigns every electrode in the box to its own read-out channel. The run is taken exactly as dragged: channels outside it keep whatever electrodes they already had. Drag several times, in different places, to build a selection that is not one contiguous block.

The on-panel hint summarizes this; Bank 2 being a half-bank (channels 0–191 only) is expected.

What you are allowed to select, and why. Every electrode is hard-wired to exactly one read-out channel: channel = electrode mod 384. A channel can read one of its electrodes at a time, so picking electrode E automatically drops whichever sibling that channel was reading. That is the only rule. Any set of electrodes is legal as long as no two of them share a channel — which the editor enforces for you, because selecting one sibling always releases the other.

Two consequences worth knowing:

  • Electrodes 768–959 (bank 2) only exist for channels 0–191. Channel 192 has no bank-2 electrode (192 + 384×2 = 960, one past the end), so the top of the shank is half-width.
  • Channel 191 is never selectable. Its three electrodes (191, 575, 959) are internal-reference sites, shown in amber. A drag that crosses them skips that channel and leaves it where it was.

Before 2026-08-27 a drag padded the dragged span out to a full 384-electrode window, so a short drag quietly selected electrodes you had not asked for. It no longer does. Use a Bank button when you want the complete uniform window.

Save / Load a map: - Save .imro — downloads the current map as a standard .imro file (via your browser's download). - Load .imro — pick a .imro file; the editor loads + displays it. Loading does not apply it — click Apply to push it to the probe.

4. Apply the map to the probe#

Click Apply Map to Hardware. SpikesPeak automatically does the safe sequence for you: pause streaming (if running) → write the new map → verify it read back correctly → resume streaming.

  • Success → status: Applied updated probe map successfully (green).
  • The Live Data view then re-labels + re-orders its traces to match the new map.

Until you Apply, edits only live in the editor — the probe keeps recording its previous map.

5. Read the live data#

Press ▶ Play (status: Streaming started) — the view switches itself to Live Data on the backend's confirmation.

📷 Live Data view with 2 columns of traces

Layout: - One trace per channel, stacked vertically and sorted by depth — the deepest electrode (probe tip) is at the bottom, shallower going up. The slider rail is labeled shallow (top) / deep (bottom). - Each trace is labeled by its electrode number + side, e.g. 100L (electrode 100, left column). Hover a label for the shank / column / read-out-channel detail. - The probe's internal-reference channel (channel 191) isn't a recording electrode, so it's pinned at the top of the right column and labeled REF (rather than mixing in with your selected electrodes by depth).

Controls:

Control What it does
Columns (toolbar) Show 1–4 chart columns side by side.
Band selector (per column) Choose the data stream — typically AP (spikes) or LFP (local field).
Shank (per column) Which shank to show. Disabled for 1.0 (single shank).
L+R / Left / Right (per column) Which electrode column(s) to show. L+R interleaves both by electrode number (0L, 1R, 2L, 3R…); Left / Right show one column, packed by depth. Tip: set column 1 = Left, column 2 = Right to view both sides at once.
Vertical slider + ▲/▼ Scroll through depth (up = shallower, down = deeper).
Window (sec) (toolbar) Time width of the view.
Click a trace label, then scroll Selects that channel and zooms its amplitude (mouse wheel). Click again to deselect.

The column header shows the electrode range currently visible (deepest ↕ shallowest).

6. Record to disk#

Recording is verified on real NP1.0 hardware (probe + NI-DAQ). See GUI-Guide.md for the full illustrated flow (name/directory prompt, channel selection, checking the result).

While playing, press ⏺ Record (it's disabled when paused). A dialog asks for a recording name and an output directory (Browse… opens a native folder picker); Set Location arms the recorder, and pressing ● Record again starts writing. SpikesPeak writes the configured streams (for 1.0, AP and LFP) to <directory>/<name>/<name>_ap_<timestamp>.bin and …_lfp_<timestamp>.bin. Press Record again to stop — streaming keeps going (only Pause stops it).

7. Disconnect / quit#

  • Disconnect releases the probe and returns the Source to "None".
  • Closing the browser quits the whole app after ~2 s (a refresh won't).

Tips & troubleshooting#

  • Play is grayed out → no source connected, or the probe isn't ready yet (watch the status box).
  • Record is grayed out → you must be playing first.
  • A channel looks identical no matter the bank → some channels can't change bank (e.g. channel 197 has no Bank 2, since Bank 2 is a half-bank). The electrode label tells you which physical site you're actually viewing.
  • The view looks upside-down / wrong order → tell the developer; orientation and ordering are configurable.
  • Anything red in the status box → open the console window; it logs the underlying error.
