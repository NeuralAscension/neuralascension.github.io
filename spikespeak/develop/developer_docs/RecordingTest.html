"Recording Test" — runbook for agents#

When the user asks for a "Recording Test", this is the exact, headless, hardware-driven end-to-end check to run and what they are looking for. It drives the live NPX 1.0 + NI-DAQ hardware on this machine via the control CLI (no GUI clicking), records a short clip, and produces two eyeball plots.

⚠️ NP2.0: everything below is Neuropixels 1.0-specific and MUST be updated for the NP2.0 multishank probe — see § NP2.0 multishank variant at the bottom.

🐧 Platform: this runbook targets the Windows hardware box (real NPX 1.0/2.0 on PXIe or a OneBox, plus the NI-DAQ). There is also a Linux box with no hardware, where the equivalent check runs against the simulated NP1.0 source; see the Linux / simulated variant below. Neither box replaced the other — no hardware row can be closed on the Linux one.

Linux: simulated NP1.0 variant (no hardware)#

On the Linux/sim box the SAME CLI flow works against the simulated source — no NI-DAQ, no probe.

  1. Python env: you need numpy + matplotlib, and pip install -e python once so plot_recording.py can import spikespeak_postprocess. On Ubuntu ≥ 23.04 a bare pip install is refused (PEP 668) — use the distro packages or a venv.
  2. Launch headless with the launcher — it reads the build's CMakeCache.txt for the exact Qt and HDF5 that built the exe, and sets QT_QPA_PLATFORM=offscreen itself when DISPLAY is unset: bash ./run_spikespeak.sh --no-browser &
  3. Drive the recording (keep < 30 s; consecutive testN under RecordingTests/, which is relative to the backend's working directory — the repo root when launched as above; teardown stop → pause → disconnect → quit). Note the config is "Simulated Data" and there is no NI-DAQ: bash python python/spikespeak_cli.py --host localhost --script \ "select 'Simulated Data'; waitready 40; probemap default; sleep 1; play; sleep 3; \ record $PWD/RecordingTests testN; sleep 8; stop; sleep 2; pause; sleep 2; disconnect; sleep 3; quit" waitready blocks on the backend's Found simulated Neuropixels 1.0 Probe. probemap bank1|bank2 also work (the sim publishes a real Bank-0 map + bank presets).
  4. Verify. python python/examples/plot_recording.py <rec> writes channels.png + sync.png. The synthetic signal is a clean sine, IDENTICAL on every channel (AP 10 Hz, LFP 4 Hz; ~250 µV σ AP / ~500 µV σ LFP) — it is purely software-generated, NOT a model of any real/damaged probe. The sync field is a clean ~1 Hz square pulse train; with no NI-DAQ band, plot_recording.py now plots the NPX sync train on its own (full + 2 s window + rising-edge zoom) instead of the NI-DAQ cross-alignment. For the ripple sim, select 'NPX 2.0 Synthetic Ripples' records the raw band AND fires the ripple detector (needs > ~7 s).

Prerequisites#

  • Hardware is physically connected; connecting a real config drives it — read Hardware safety in ../CLAUDE.md first (never force-kill a backend with a probe or OneBox open).
  • Build is current. If you changed C++, rebuild first (Building.md). Frontend and config edits need no build: the exe in bin/ reads webinterface/, config/ and imro_maps/ straight out of the repo, so just relaunch — or hard-reload the browser (Ctrl+Shift+R) for .js/.css.
  • Launch through run_spikespeak.bat, which puts Qt + HDF5 + the vendored Neuropixels DLLs on the loader path (running bin/SpikesPeak.exe directly exits 0xC0000135). It reads the build's own CMakeCache.txt to find them, so there is no path to edit here. See ControlCLI.md.

Steps#

  1. Launch headless (no browser tab left open — without --no-browser the backend opens one in the operator's default browser, on top of whatever you are driving): powershell # Run from the repo root: the backend's WORKING DIRECTORY decides where RecordingTests\ lands. Start-Process -FilePath ".\run_spikespeak.bat" -ArgumentList "--no-browser" -WindowStyle Hidden # then poll TCP 1234 until it is listening. # Backend logs go to output.log in that working directory, NOT to stdout: the exe is a # windowless GUI-subsystem process, so a redirected pipe stays empty.
  2. Drive the recording via the CLI (keep each recording < 30 s; name it the next consecutive testN under <repo>\RecordingTests\). Correct teardown is stop → pause → disconnect → quit: bash python python/spikespeak_cli.py --script \ "select 'NPX 1.0 with NI-DAQ'; waitready 40; probemap default; sleep 2; play; sleep 3; \ record <repo>/RecordingTests testN; sleep 15; stop; sleep 2; pause; sleep 2; disconnect; sleep 3; quit" waitready blocks on the backend's Found Neuropixels 1.0 Probe status. For a bank test, swap probemap default for probemap bank1 / probemap bank2 (NP1 only).
  3. Plot + verify (writes sync.png + channels.png INTO the recording folder): bash python python/examples/plot_recording.py <repo>/RecordingTests/testN
  4. Confirm the process exited (a clean quit, never a force-kill with the probe open). Any capture you redirect belongs in your session scratchpad, not in the repo.

The config under test#

config/Npx1PxiNiDaq.yaml ("NPX 1.0 with NI-DAQ") records all 384 read-out channels on AP (@30 kHz) and LFP (@2.5 kHz), plus all 8 NI-DAQ analog channels and the 8 digital lines (nidaq_di) @40 kHz. It was widened from [1, 192, 196] to the full list on 2026-07-17; the comment inside the file still describes the old three-channel selection — the list under it is the authority.

The profile is gui_hidden, superseded for everyday use by PXIe with NI-DAQ (which resolves the basestation from a scan instead of being told), but it stays selectable by exact name — which is what the CLI line above does, and why published runbooks keep working.

Narrow the recording before you plot. plot_recording.py draws one stacked subplot per recorded channel (plot_channels()), so a 384-channel AP + LFP pair asks it for 768 rows and no usable figure comes out. For the eyeball test, record a handful of channels — the GUI record-channel picker, or a channels: list in your own copy of the profile — or plot a subset yourself with spikespeak_postprocess. Electrodes 192 and 196 are the traditional pick: their amplifiers read more variable (suspected damaged), so they stand out against a quiet e1.

What the user is looking for#

  • channels.png — AP and LFP blocks for the electrodes you recorded, per-band shared µV scale:
  • e1 should look clean/quiet; e192 / e196 visibly noisier (bigger σ / peak-to-peak, spiky artifacts). This is the "damaged amp" proof AND confirms both AP and LFP bands are recording.
  • sync.png — NI-DAQ↔NPX timestamp sync (a shared TTL pulse train on the NPX sync field + NI-DAQ ch0): 4 rows = full native, full aligned, and a rising-edge zoom pre-sync (both edges + the native offset, e.g. +3.94 ms) and post-sync (NPX + aligned NI-DAQ overlapping). Confirms the drift correction works (expect a few ppm, sub-ms residual). If there's no shared pulse train it still renders the raw signals with a "no drift fit" note.
  • Clean teardown — no hang; the probe is released (a mid-stream disconnect used to leave it bad).

Bank-test caveat (electrode vs read-out channel)#

The config channels: are electrode numbers assuming the default Bank 0 map (where electrode == read-out channel). A probemap bank1/bank2 changes which electrode each read-out channel carries, but the recorder still writes the same read-out channels. So under bank1/bank2 those channels read different electrodes and the data changes (that change is the proof the bank reached the hardware) — but the sidecar's electrode labels are still the Bank-0 numbers. Bank presets load imro_maps/npx1_bank{0,1,2}.imro; bank2 is a partial bank (ch 0–191 → bank 2, ch 192–383 → bank 1).

NP2.0 multishank variant (2026-07-06)#

NP2.0 multishank is now at parity (Status §15). The SAME CLI flow works; the key differences from 1.0:

  • Config / bands: NP2 is a SINGLE raw band (30 kHz), not ap/lfp. Use config/Npx2Pxi.yaml ("NPX 2.0 Multishank", now has a proc.npx.recorder + proc.lfp) or NpxPxiNiDaq.yaml for 2.0 + NI-DAQ. rec.bands() returns ['raw'] (+ ['nidaq']). The derived LFP comes from proc.lfp (not a recorded band).
  • No bank presets: probemap bank1|bank2 is (correctly) REJECTED for NP2. Use default (shank 0, Bank A) or an NP2 .imro path. In the GUI editor use the Shank dropdown + Bank A-D presets.
  • Readiness: the backend reports Found Neuropixels 2.0 Multishank Probe; waitready keys on "found … probe" so it still works.
  • Sync: the NPX sync field + spikespeak_postprocess.synchronize(reference_band="raw", …) carry over.

Hardware-free (simulated 2.0) — the readily-runnable check on ANY box:

# Run from the repo root; a relative <dir> is resolved against the BACKEND's working directory.
python python/spikespeak_cli.py --host localhost --script \
 "select 'Simulated NPX 2.0 Multishank'; waitready 40; probemap default; sleep 1; play; sleep 3; \
  record $PWD/RecordingTests np2simN; sleep 8; stop; sleep 2; pause; sleep 2; disconnect; sleep 3; quit"

The raw .bin is a clean sine IDENTICAL on every channel (10 Hz + 4 Hz components; the 4 Hz shows up in the derived LFP), with a ~1 Hz sync square. select 'Simulated NPX 2.0 Multishank + NI-DAQ' also records the NI-DAQ band and rec.synchronize(reference_band="raw", nidaq_sync_channel=0) recovers the ~10 ppm drift. A headless-Chrome smoke test of the 4-shank editor / record-selection / live view is the GUI suite: python scripts/run_gui_tests.py. (This line used to name cdp_np2_smoke.py, a one-off that has not existed since those checks moved into tests/gui/ — a runbook naming a script nobody can find is worse than one that names none.)

Real 2.0 probe: select 'NPX 2.0 Multishank', then the same flow. Confirm the log shows writeProbeConfiguration VERIFIED OK on probemap default/Apply. Pick NP2 read-out channels for the channels: list (the default map is all shank 0).
