Benchmarks#

Two independent benchmarks live here:

  1. Rendering channel-density — how render cost scales with the number of live traces. This is the benchmark that decides the SciChart → WebGL switch. Files: cdp_bench.py, plot_density.py, bench_channel_density*.csv, bench_channel_density.png, CHANNEL_DENSITY_REPORT.md.
  2. Ripple-filter threading (separate) — bench_ripple_filter.cpp + plot_bench.py, documented in developer_docs/RippleDetectorThreading.md.

This README covers #1: everything needed to replicate the SciChart ↔ WebGL comparison later.

What it measures#

cdp_bench.py drives the running GUI over CDP and sweeps columns × traces-per-strip (COLS=[1,2,4] × TRACES=[20,40,60,80] → 20…320 on-screen series) while traces are actually drawing. Per config it records: fps, frame time mean/p95/max ms, JS heap MB, main-thread busy fraction (Chrome TaskDuration delta ÷ wall-time — the true ceiling), and a bound point-count sanity (>0 = traces really rendering, guards the blank-surface trap). Output: bench_channel_density<_label>.csv + one screenshot per config under shots/. plot_density.py renders the 4-panel figure.

SciChart baseline (measured on this rig)#

sim NP2 Multishank, 384-ch RAW @ 30 kHz, 1920×1080, primary monitor: - solid 60 fps to ~160 series; 4×60 = 86% main-thread; 4×80 = 100% saturated → ~45 fps. - Frozen baseline: bench_channel_density_scichart.csv (== bench_channel_density.csv); write-up in CHANNEL_DENSITY_REPORT.md.

Reproduce (either renderer)#

Prereqs — one backend + one isolated Chrome on CDP:9222 (see developer_docs/GuiTesting.md):

python run_spikespeak.py --no-browser          # Windows (or the Linux offscreen build)
chrome --remote-debugging-port=9222 "--remote-allow-origins=*" \
  --user-data-dir=<tmp>/sp_bench_profile --app=http://localhost:8234 --window-size=1920,1080

Then:

python benchmarks/cdp_bench.py           # -> bench_channel_density.csv     (current renderer)
python benchmarks/plot_density.py        # -> bench_channel_density.png

Both scripts are portable (repo-relative, no hard-coded machine path) and the measurement is engine-independent.

Comparing SciChart vs WebGL (after the refactor)#

  1. The SciChart baseline is already frozen: bench_channel_density_scichart.csv.
  2. Build/serve the WebGL renderer, then run the SAME sweep with a label (keeps it from clobbering the baseline): python benchmarks/cdp_bench.py webgl # -> bench_channel_density_webgl.csv python benchmarks/plot_density.py benchmarks/bench_channel_density_webgl.csv # -> bench_channel_density_webgl.png
  3. The point-count sanity is renderer-agnostic via ONE hook: the WebGL renderer must expose window.__benchPointCount(colIndex) (on-screen sample count for that column). cdp_bench.py calls it first and falls back to SciChart's onScreenSeries[0].dataSeries.count(). Implement that hook and the whole harness works unchanged.
  4. Compare _scichart vs _webgl at each (cols×traces). Target: 4×384 @ 60 fps, main-thread < 50% (the SciChart wall was 4×80). Full plan: developer_docs/NextPrompt_GUI_WebGL_Refactor.md.

Notes#

  • cdp_bench.py's SETUP block assumes current DOM ids (selectSource, #sim-picker-card, tab-btn-map/tab-btn-data, playPauseBtn, btn-apply-imro, colsSel, __tracesOverride, __perfStats). If the refactor renames these, update the setup block only — the metrics loop is engine-independent.
