OpenEphys Neuropixels 2.0 (multishank) — reference#

Exactly how the vendored OpenEphys plugin (Source-OpenEphys-Neuropixels-PXI/) drives NP2.0 multishank probes, distilled for our implementation. This is the reference; our plan + gaps are in Neuropixels2.0.md. All file:line are within Source-OpenEphys-Neuropixels-PXI/.

⚠️ Key correction vs the earlier guess: NP2 channel↔electrode is not channel + 384*bank. Within a shank the bank sets the electrode range, but the channel for an electrode comes from a per-shank block-permutation lookup table (Probes/Geometry.cpp). See §2.

1. Probe model & geometry (Probes/Geometry.cpp:219-514, Neuropixels2.cpp:45-148)#

NP2.0 single (NP2_1, id 21) NP2.0 multishank (NP2_4, id 24)
shanks 1 4 (0–3, independent)
electrodes / shank 1280 1280 (5120 total)
read-out channels 384 384 total, shared across shanks
banks / shank 4 — A,B,C,D (384 electrodes each) 4 — A,B,C,D
columns / shank 2 (left col=i%2==0, right ==1) 2
rows / shank 640 (electrodes 7.5 µm apart vertically) 640
per-channel gain none (fixed) none
per-channel AP filter none none
sample rate 30 kHz (AP only; no separate LFP) 30 kHz

Geometry per electrode (Geometry.cpp:357-375):

shank             = global_index / 1280
electrode_local   = global_index % 1280          // 0..1279
bank (A/B/C/D)    = electrode_local / 384         // 0,1,2,3  (D is partial: 1152..1279)
column            = electrode_local-derived i%2   // 0=left,1=right
row               = electrode_local / 2           // within shank
xpos = (i%2)*32 + 27 µm ;  ypos spaced 15 µm per row-pair

2. Electrode ↔ channel ↔ bank ↔ shank wiring (Geometry.cpp:380-507)#

The 384 channels are distributed across the 4 shanks via per-shank lookup tables. Within a shank, each 384-electrode bank is split into 8 blocks of 48; each block maps to a channel offset by a shank-specific permutation. Shank 0:

int block       = (electrode_local % 384) / 48 + 1;   // 1..8
int block_index = electrode_local % 48;               // 0..47
// channel = block_index + 48 * P0[block]   where P0 = {0,2,4,6,5,7,1,3}

Shanks 1/2/3 use different permutations (Geometry.cpp:412-507). Net: channel = lookup(shank, electrode_local), and bank = electrode_local/384. To build a map you pick electrodes; the lookup yields each electrode's channel + bank; conflicts (two chosen electrodes mapping to the same channel) are illegal.

For OUR live view this detail doesn't matter — we already get (channel, shank, electrodeId) straight from the IMRO and treat electrodeId as within-shank (row=e>>1, col=e&1). The lookup tables matter for the editor (choosing electrodes) and for building a default map in C++.

3. Default selection & presets (Neuropixels2.cpp:69-130, 307-625)#

Default: all 384 channels → Bank A, shank 0, each channel's natural electrode (selectedBank=A; selectedShank=0; selectedElectrode=electrodeMetadata[i].global_index).

Named presets (useful as our default-map options): - Per shank × bank: "Shank {1-4} Bank {A-D}" — e.g. Shank 2 Bank A = electrodes 1280..1663. - Cross-shank: "All Shanks 1-96", "…97-192", … — electrodes N+1280*shank for shank 0..3 (96 electrodes per shank). Geometry.cpp:467-477.

4. Hardware configuration sequence (Neuropixels2.cpp)#

Per selectElectrodes() → setAllReferences() → writeConfiguration():

// 1) per channel (Neuropixels2.cpp:294-302)
Neuropixels::selectElectrode(slot, port, dock, channel, shank, bankIndex);   // bankIndex: 0=A..3=D

// 2) per channel (Neuropixels2.cpp:689-705)   -- NP2_4: first DISCONNECT all 4 shank switches:
for (shank 0..3) Neuropixels::setReference(slot,port,dock, 0, shank, NONE_REF, 0);
Neuropixels::setReference(slot, port, dock, channel, shank, refId, intRefBank);

// 3) once (Neuropixels2.cpp:715-720)
Neuropixels::writeProbeConfiguration(slot, port, dock, /*read_check=*/false);

Init path (Neuropixels2.cpp:176-181): init() → writeProbeConfiguration(...,false) → bistSR() shift-register self-test returning a per-shank OK mask (a failed shank is marked non-programmable).

No setGain / setApFilterState for 2.0 — those are empty (Neuropixels2.cpp:627-635).

API signatures (API/NeuropixAPI.h):

NP_ErrorCode selectElectrode(int slot,int port,int dock,int channel,int shank,int bank);     // :1202
NP_ErrorCode setReference(int slot,int port,int dock,int channel,int shank,
                          channelreference_t reference,int int_ref_electrode_bank);           // :1242
NP_ErrorCode writeProbeConfiguration(int slot,int port,int dock,bool read_check);             // :939
// channelreference_t: EXT_REF=0, TIP_REF=1, INT_REF=2, GND_REF=3, NONE_REF=0xFF              // :174

5. References (Neuropixels2.cpp:93-99, 645-705)#

Options: Ext, 1: Tip … 4: Tip (tip ref per shank), Ground. Mapping: Ext→EXT_REF, "k: Tip"→TIP_REF with shank=k-1. For NP2_4 + EXT_REF, use the channel's own shank. Multishank disconnects all four shank switches (NONE_REF) before setting the chosen reference.

6. IMRO format (Formats/IMRO.h:113-146, 367-401)#

Header (24,384) — 24 = NP2_4 part id, 384 = channels. Then one entry per channel:

(channel  shank  bank  reference  electrode_within_shank)
   0-383   0-3   0-3   0=Ext|1-4=Tip   0-1279

electrode_within_shank = selectedElectrode − 1280*shank. Example:

(24,384)
(0  0 0 0 100)     # ch0,  shank0, bankA, Ext, electrode 100
(96 1 0 0 50)      # ch96, shank1, bankA, Ext, electrode 50

This matches SpikesPeak's parser/serializer already — parseImroContent/serializeImro use (channelId shank bank refId electrodeId), 5 fields, same order (NpInterface.cpp). So loading an OpenEphys NP2_4 .imro should populate our map and our live-view geometry correctly. The gaps are the C++ default map + hardware apply, and the JS editor — see Neuropixels2.0.md.

7. The interactive editor (UI/NeuropixInterface.cpp, UI/ProbeBrowser.cpp)#

OpenEphys draws all shanks side by side; the user paints electrodes (per shank), and selecting an electrode assigns its channel (via the §2 lookup) and deselects whatever else used that channel. It enforces one-electrode-per-channel and surfaces bank/shank conflicts. This is the model to mirror in our ImroManager.js NP2 branch (today a non-interactive placeholder grid).

8. Mapping to our code (what to build — see Neuropixels2.0.md)#

  • Default map (NpInterface.cpp:548 stub) → emulate Neuropixels2 default (all ch, shank 0, bank A) or a preset; set probeIdStr="24", fill channels[] with {channelId, shank, bank, refId, electrodeId(within-shank)}.
  • Apply (NpInterface.cpp:745 stub) → the §4 sequence: per-channel np_selectElectrode(...,shank, bank) + np_setReference(...,shank,...) (disconnect shanks first), then the existing np_writeProbeConfiguration(read_check=true) verify. No gain/filter calls.
  • Editor → a 4-shank selectable map in ImroManager.js, using the §2 lookup for channel assignment.
