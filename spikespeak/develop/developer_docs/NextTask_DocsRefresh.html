How to recapture#

tests/gui/_harness.py drives it. Set the source with the env var, and use the right display:

os.environ["SPIKESPEAK_GUI_SOURCE"] = "NPX 1.0 (OneBox)"   # or a Simulated … name
with Gui(monitor="landscape") as g:   # "portrait" for vertical shots
    g.live_view(settle=10); g.columns(3)

Traps that will otherwise waste a pass:

  • The Probe Map | Live Data tabs appear only once initProbeMap succeeds — i.e. when the selected source registers a probe object with getImroAsJson. The source's name is not consulted: the old name: contains "NPX" gate went with the source-selection refactor (main.js and NetworkClient.js both carry the comment), so SimNpx1.yaml — still named "Simulated Data" — shows the tab bar too. Pick the source for what it publishes, not what it is called.
  • Play/Record have an in-flight PENDING state (dimmed, pulsing, disabled). Wait for it to settle or the button screenshot captures the wrong meaning.
  • A strip collapses when one row (448px) does not fit beside the depth readout — not past a column count. On the 1920 landscape display 3 columns are 628px wide, which leaves 477px beside the depth readout for a 448px band, so the strips are already open; document.querySelectorAll('.cc-pin').forEach(b => b.click()) there does not reveal anything, it toggles — unpinning any column main.js re-pinned from its app-level set, and arming a pin that only shows itself after the next buildColumns(), when the shot is already taken. Pin only what is actually collapsed, and only if it is not pinned already:

js document.querySelectorAll('.column-container.strip-collapsed:not(.strip-pinned) .cc-pin') .forEach(b => b.click());

A pinned band is position: absolute and lands over the top of the traces, so prefer a state where it fits in flow (fewer columns, wider window, ripple dock shut) and pin only when the shot must show a band that genuinely cannot fit. The rule and its arithmetic are in LiveDataView.md §4.
