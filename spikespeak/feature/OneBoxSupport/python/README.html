spikespeak_postprocess#

Load SpikesPeak recordings — Neuropixels 1.0 AP / LFP bands and NI-DAQ — addressed by the electrode number you saw on screen, as NumPy arrays or xarray DataArrays.

Why it "just works"#

Every recorded .bin file has a self-describing <file>.bin.json metadata sidecar written by the SpikesPeak backend (RecordProcessor) at record time. It carries the band, record layout, sample rate, units, and the channel/electrode list — so this package needs no out-of-band knowledge of the recording.

Install#

cd python
pip install -e .            # core (numpy)
pip install -e .[xarray,plot]   # + xarray + matplotlib for the example

Use#

from spikespeak_postprocess import Recording

rec = Recording(r"C:/Data/mouse42")     # the folder you chose in the Record dialog
rec.bands()                              # ['ap', 'lfp', 'nidaq', 'nidaq_di']
rec.channels("ap")                       # electrodes recorded for AP, e.g. [1, 2, 3]

# --- NumPy ---
sig = rec.load(channels=[1, 2], band="ap", output="numpy")
sig.data            # (n_samples, 2) int16 ADC
sig.time            # (n_samples,) seconds
sig.channels        # [1, 2]  (electrode numbers, column order)
sig.fs              # 30000.0
uv = sig.to_microvolts()                 # (n_samples, 2) in µV

# LFP electrode 2, and all NI-DAQ channels
lfp = rec.load(channels=2, band="lfp")
daq = rec.load(band="nidaq")             # all recorded NI-DAQ analog channels (volts)

# --- NI-DAQ DIGITAL lines (DI/O) ---
# The NI-DAQ port0 lines are recorded as the "nidaq_di" band: each channel is a 0/1 logic line
# (e.g. the Neuropixels 1.0 sync pulse rides one of them). It loads as a digital Signal.
rec.digital_lines("nidaq_di")            # {0:('high',0), 1:('low',0), 2:('toggling',N), ...}
di  = rec.load(band="nidaq_di")          # di.units == "logic", di.digital is True, values are 0.0/1.0
hi  = di.as_bool()                       # boolean (n_samples, n_lines); to_microvolts() is refused
sync = rec.load(channels=2, band="nidaq_di")   # just the toggling sync line

# --- xarray ---
da = rec.load(channels=[1], band="ap", output="xarray")   # dims (time, channel)

channels are electrode numbers for ap/lfp (what the live view shows; equal to the read-out channel for the default Bank-0 map) and channel indices for nidaq. Requesting an electrode that wasn't recorded raises a clear error listing what was.

Synchronizing NI-DAQ ↔ Neuropixels (clock-drift correction)#

Feed one shared TTL/sync pulse train to both the Neuropixels sync input (recorded in the NPX sync field) and one NI-DAQ analog channel. The same pulses then appear in both files, so their rising edges pin the two clocks together and correct for drift:

model = rec.synchronize(reference_band="ap", nidaq_sync_channel=0)   # NI-DAQ ch 0 carries the pulses
print(model.drift_ppm, model.residual_ms)     # e.g. -51.3 ppm, 0.02 ms RMS  (alignment quality)

daq = rec.load(band="nidaq", sync=True)        # daq.time is now on the Neuropixels clock
# or apply the map yourself:
t_npx = model.apply(daq.raw_timestamps / daq.fs)

This ports polling-latency.ipynb's align_with_drift_correction with improvements: - Linear warp by default — clock drift is a near-constant rate, so a least-squares line is robust and won't blow up on extrapolation the way the notebook's quadratic interp1d can (kind="quadratic"/"interp" reproduce it; "interp" needs SciPy). - Adaptive edge threshold (per-signal min/max midpoint) — handles a 0/1 NPX bit and a several-volt NI-DAQ analog pulse without tuning. - Robust nearest-edge pairing by default (match="auto") — pairs the two pulse trains by nearest edge, so a capture-count asymmetry at either end can't cause the off-by-one that silently shifts latency by a whole sync period. A pulse-count mismatch (and any residual interval disagreement) is warned about, not hidden; match="end"/"start" remain for explicit one-to-one end/start pairing. - Diagnostics — drift_ppm and residual_ms so you can see the alignment quality (residual should be sub-millisecond).

The low-level function is exposed too: align_timestamps(ref_time, ref_sync, target_time, target_sync, kind="linear", match="auto"). Example with the before/after verification plot: python examples/synchronize_nidaq.py <dir> [ch] [band].

Example — plot a channel#

python examples/plot_channel.py C:/Data/mouse42            # random AP electrode
python examples/plot_channel.py C:/Data/mouse42 lfp 2      # LFP electrode 2
python examples/plot_channel.py C:/Data/mouse42 nidaq 3    # NI-DAQ channel 3

Example — save the two standard plots into a recording folder#

python examples/plot_recording.py C:/Data/mouse42          # writes sync.png + channels.png in that dir

sync.png = NI-DAQ↔NPX timestamp sync (before/after drift correction); channels.png = the recorded AP electrodes over the first 2 s on a shared µV scale (so a noisier/damaged channel stands out). 12×4-inch PNGs. Robust: if there's no shared sync pulse train, sync.png still renders the raw signals.

Record layouts (from the sidecar record_format)#

record_format bytes per record units
npx uint32 ts · uint16 sync · int16 × N adc_int16 (→ µV via default gains: AP 500, LFP 250)
nidaq float64 ts · float64 × N volts (→ µV = ×1e6)
nidaq_di float64 ts · float64 × N (same nidaq format) logic (0/1 digital lines; .digital=True, use .as_bool())

N = number of channels in the recording's channels: list. Microvolt conversion assumes the default IMEC gains (AP 500 / LFP 250); if you change the gain in the IMRO panel, scale accordingly.

Export to Open Ephys binary — convert_to_openephys.py#

Offline converter to the Open Ephys "Binary" record-engine format (the tree the Open Ephys GUI, open-ephys-python-tools and SpikeInterface open). Nothing touches the acquisition path; numpy only.

# ALWAYS scan first: it reconstructs the sample index and reports dropped samples. Writes nothing.
python python/convert_to_openephys.py scan  RecordingTests/2026-08-25_throughput_repro/A_withadc_t15
python python/convert_to_openephys.py openephys <recording_dir> <out_dir>
python python/convert_to_openephys.py openephys <in> <out> --adc-range 2.5      # ADC not at ±5 V
python python/convert_to_openephys.py openephys <in> <out> --bit-volts ap=0.195 # gain not default

from spikespeak_postprocess import openephys
openephys.scan(src)                 # gap report, no writes
openephys.export(src, out_dir)      # -> <out>/Record Node 101/experiment1/recording1/

Every (recording_name, timestamp) session in the directory becomes its own recording<M>, and every band becomes a continuous/SpikesPeak-101.<band>/ stream. The per-frame sync word is decoded to a TTL event channel when it actually has edges.

Dropped samples survive. Open Ephys carries an explicit sample_numbers.npy, and a gap lives in the divergence between the row index in continuous.dat and the value there — continuous.dat is never padded, exactly as the Open Ephys writer behaves. So sample_numbers[-1] - sample_numbers[0] + 1 > len(sample_numbers) precisely when samples were lost, and scan prints where and how many. (The GUI's own File Reader ignores interior gaps — it reads sample_numbers[0] and treats the rest as contiguous — so a replay inside the GUI slides post-gap data earlier. The gap is in the file and numpy readers see it; that is their reader, not a reason to pad.)

Reconstructing the index is the whole job, because the NPX frame timestamp is 100 kHz hardware ticks, not samples (kHeadstageSamplingRate): at 30 kHz consecutive frames differ by 3 or 4 and never by 1, so diff != 1 is not a gap test. The rule is per-frame, advance = max(1, round(Δticks / (100000/fs))) then cumsum, with the uint32 wrap corrected first. NI-DAQ is different again — its float64 timestamp already is a sample index.

A fabricated gap is refused too. The mirror of the rule above: the converter must not invent sample numbers either. Where a frame's timestamp does not advance, the reconstruction has to force +1 to keep the index increasing — fine for one damaged frame, catastrophic when it is systematic. Real NP1.0 ap bands are systematic: inside each 12-sample IMEC packet the stamps run ahead at ~4.36 ticks/sample and then step back by 8 (netting exactly 40 ticks = 12 samples), so one frame in twelve goes backwards. Reconstructed naively that band comes out 1.3055× too long with 5 671 337 invented single-sample gaps — measured on RecordingTests/np1_2ch_q2_asap, a recording that lost nothing (its lfp band is exactly uniform and the ap tick span matches the frame count). So the band is refused, with the measured inflation in the message; convert --bands lfp instead. scan reports it as timestamps_usable: false + index_inflation without raising, so the dry run still tells you everything. The check is a pre-flight over every band before a byte is written, so a refusal never leaves a half-written tree.

⚠️ The two converters disagree about NP2.0 microvolts, by 3.81×. Both pass the int16 counts through untouched; only the declared scale differs. SpikesPeak's own constant (backend, live view, developer_docs/Recording.md) is 1.0 V / 84 / 4096 = 2.9064 µV/count; SpikeGLX/IMEC describe the same probe as 0.5 / 8192 / 80 = 0.7629 µV/count. For NP1.0 the two agree exactly (2.34375), which is what shows the arithmetic is right and the NP2.0 constant is the outlier. Nothing in a v1 sidecar settles it — the metadata_version: 2 scale block will. Until then it is an operator decision; pass bit_volts explicitly if you know the answer. A test pins the ratio so the two cannot drift further apart silently.

Scaling is a pass-through and says so. int16 counts in, the same int16 counts out, with only bit_volts declared — exact and reversible, unlike Open Ephys's native round(µV/bit_volts) path. But bit_volts is not in the SpikesPeak sidecar (it records units: "adc_int16" and no more), so the defaults below come from the backend's own display constants and each carries its assumption into structure.oebin → spikespeak and into every channel's description.

band bit_volts units assumes
ap 1.2e6/1024/500 = 2.34375 µV IMEC AP gain 500
lfp 1.2e6/1024/250 = 4.6875 µV IMEC LFP gain 250
raw 1e6/84/4096 = 2.9064 µV NP2.0 fixed 84× gain
adc --adc-range/32768 V OneBox ADC range, default ±5 V — not recorded in the sidecar
nidaq --nidaq-range/32768 V float64 volts → int16 is lossy; refused unless you opt in

A band with no known factor is refused, not guessed — a wrong bit_volts silently misscales every trace and nothing in the output would reveal it. The same goes for a sidecar that contradicts itself, an unknown record_format, or a channel list that disagrees with the frame width.

Tests: python python/tests/test_openephys_export.py (stdlib unittest + numpy, no hardware).

Sibling tool: spikespeak_cli.py (headless control)#

python/spikespeak_cli.py drives a running SpikesPeak backend over its WebSocket with no GUI clicking — select → probemap → play → record <dir> <name> → stop → quit — so you can script a whole acquire + record run and then load it back with this package. Zero dependencies (stdlib only). It's how the recording pipeline is regression-tested end-to-end. See developer_docs/ControlCLI.md.

Sibling tool: convert_to_spikeglx.py (export to SpikeGLX)#

python/convert_to_spikeglx.py converts a finished recording into SpikeGLX 3.0 .bin/.meta pairs so it can be read by SpikeGLX's own FileViewer, CatGT, TPrime and SpikeInterface. Offline, numpy only, nothing on the acquisition path.

python convert_to_spikeglx.py <recording_dir> <out_dir> --probe np2-4shank
python convert_to_spikeglx.py <recording_dir> <out_dir> --probe np1 --band raw --dry-run
SpikesPeak band SpikeGLX stream notes
raw, ap <run>_g0_t0.imec0.ap needs --probe; carries a synthesised default ~imroTbl
lfp <run>_g0_t0.imec0.lf acquisition indices 384..767
adc <run>_g0_t0.obx0.obx OneBox ADC; --adc-range (default 5 V)
nidaq <run>_g0_t0.nidq float64 volts → int16 is lossy, so it needs --nidaq-range
nidaq_di <run>_g0_t0.nidq 0/1 lines packed losslessly into one XD word

A gapped recording is REFUSED, never padded. A SpikeGLX .bin is a dense int16 matrix whose .meta holds exactly one time anchor (firstSample), so a dropped-sample gap is inexpressible; padding it would make a fault look like clean data. The converter audits the recorded per-frame timestamps first and, on any gap, rollover or off-grid step, prints where and how much and exits non-zero without writing anything. There is deliberately no --pad and no --force. (The timestamp is a 100 kHz tick counter, not a sample index — consecutive deltas legitimately alternate 3 and 4 at 30 kHz — so the test is rint(Δ / (100000/fs)) == 1.)

The samples themselves are copied bit-for-bit: SpikeGLX's V = i·imAiRangeMax/imMaxInt/gain is numerically identical to this package's µV/LSB, so the conversion lives entirely in the .meta. --probe is required for a neural band because the sidecar does not record the probe and the probe is what sets that scale. Assumptions that cannot be read from the recording (probe, ADC range, default Bank-0 map, synthesised IMRO) are written into userNotes.

from spikespeak_convert import convert_to_spikeglx, ConversionRefused
convert_to_spikeglx(r"C:/Data/mouse42", r"C:/Export", probe="np1")

Tests: python tests/test_spikeglx_convert.py (stdlib unittest + numpy).
